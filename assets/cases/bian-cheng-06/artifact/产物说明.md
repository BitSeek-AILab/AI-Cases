# 产物说明 · 运营数据看板（案例编程-06）

## 一、这是什么

**一个单文件 HTML 数据看板**：双击就能打开，一眼看到关键数字，并且能自己改口径（不用部署、不用授权、不用求人）。

| 项 | 值 |
|---|---|
| 文件 | `运营数据看板.html` |
| 体积 | **68,450 B（约 66.8 KB）** |
| md5 | `77cbc09666af15160ed229cd50246df8` |
| 依赖 | **零**。零 CDN、零外部字体、零图片、零图表库、零构建 |
| 打开方式 | 双击（`file://`）即可；离线可用 |
| 数据 | **页面内 JS 生成**（固定种子 `20261012` 的 mulberry32，40 SKU × 60 天 = 2400 行），**全部为虚构演示数据**（页脚已注明）|

## 二、页面上有什么（从左到右、从上到下）

1. **过滤器行**（一整行，作用于下面**全部**内容）：时间范围 `近 7 天 / 近 14 天 / 近 30 天`。
2. **hero 读数带**（本页的签名元素）：**本期净销售额**（GMV − 退款，大数字）+ **较上期**方向与幅度 + **上期金额** + **30 点净销售额 sparkline 丝带**。
3. **6 个 KPI 磁贴**：订单数 / 客单价 / 支付转化率 / 访客数 / 退款率 / 新增会员。
   每个都带 **12 点 sparkline** + **较上期 ±%**（颜色按"方向 × 这个方向是不是好事"给：退款率上升是坏，用警示色 + ▲）。
4. **每日 GMV · 本期 vs 上期**（折线，双系列）：**十字准线 + 读数窗一次列出本期/上期/环比**；端点直标；下方 `表格视图`（30 行真表格，不用悬停也能读到每个值）。
5. **渠道 GMV 对比**（横向条形，**单色**）：条端标金额，左列标渠道名与占比。
6. **品类 GMV 占比**（100% 堆叠条）：段内标占比，图例给出每个品类的**占比 + 金额**。
7. **商品明细**（40 行）：9 列，**点表头排序**、品类 chip × 渠道下拉（**可叠加**）、搜索、"显示 N / 共 M"、无命中时给空状态 + 一键清空。
8. **页脚**：口径说明 + 数据源与固定种子 + 虚构声明。

## 四、这些结论是**怎么验出来的**（不是"我觉得对"）

- **82 项功能与视觉核验全过，页面 JS 错误 0** —— `质检/verify_result.json` + `verify_dashboard_log.txt`（真开 headless Chrome，真实鼠标/键盘事件）。
  复跑：`node 阶段3_功能与视觉核验/verify_dashboard.mjs 最终产物/运营数据看板.html 阶段1_数据与结构设计/产物/演示数据_参考.json 最终产物/质检 最终产物/质检/verify_result.json`
- **"页面里那份数据"不是随口编的**：`阶段1/make_reference.py` 是同一套规格的 **Python 独立实现**，页面内 JS 生成的行数据与它的**逐行 SHA-256 完全一致**
  （`e06a5159f5efec8410e9be4a99191992466261f85449ee751dd89cc74035939a`）。换个种子哈希立刻不匹配 —— 这说明"固定种子"是真的。
- **数字对得上**：hero 与 6 个 KPI 在 7 / 14 / 30 三个切片下，都与参考实现的真值**逐项相等**；"渠道合计 == 品类合计 == 本期总 GMV"三方一致。
- **图不是空壳**：三张图的 mark 数量 == 切片数据条数；坐标全部是有限数、全部落在 viewBox 内；折线的 y 值由核验脚本**自己重算**（最大偏差 0.0050px）。
- **配色不是眼看过去的**：跑了 dataviz 自带的调色板校验器（`质检/palette_validation.txt`）——light 5 槽全 PASS，dark 全 PASS。
- **手机不横滚是"摘掉遮羞布之后"量的**：390 / 320 两个宽度都断言了 `window.innerWidth` 严格等于目标值，**并且**在移除 `overflow-x` 与 `.console` 的 `overflow:hidden` 之后再量 `scrollWidth`。
- **11 张截图逐张看过**（文件名自带 `-light`/`-dark`，因为本机系统偏好是深色，不钉住主题会深浅混着出）：
  `质检/*.png`（桌面浅色 5 张：首屏 / tooltip / 明细表 / 空状态 / 全页；桌面深色 1 张；手机 390 三张；320 两张）+ `质检/MD5清单.txt` 逐文件 md5。
- **独立审查 Agent 复审通过（准予交付）**：它自己跑了核验、自己从零写了一份 Python 生成器复算（哈希逐字节一致）、自己打开 11 张截图取证；结论见 `自检表.md` 第六节，其指出的 3 条非阻断意见已逐条修订并重跑通过（第七节）。

## 五、口径（页脚同款，抄在这里免得找不到）

- **净销售额 = GMV − 退款额**；GMV 为当期成交金额。
- **退款率 = 退款额 ÷ GMV**（**金额**口径，不是件数口径）。
- **客单价 = GMV ÷ 订单数**；**支付转化率 = 订单数 ÷ 访客数**。
- 明细表里的 **⚠ 偏高** = 该 SKU 的退款率高于**本期切片均值 × 1.25**（警示线随切片滚动，页面上会写明具体数值）。

## 六、边界与已知限制（如实说明）

1. **数据是虚构的**：40 个商品名与 SKU 码均为编造，不与任何真实品牌/店铺/平台对应。
2. **没有接真实数据源**：把页面里的 `buildData()` 换成 `fetch('/api/orders')` 就是生产看板 —— 这是最后一步、也是最简单的一步。
3. **退款只到金额，没有件数**，所以退款率是金额口径。
4. **没有成本字段**（投放花费、达人佣金），因此**不做 ROI / 毛利**。要做就得编成本数据，那才是真的失真。
5. **手机可读性未做真机测试**：结论来自 CDP 设备模拟（390×844 / 320×720）。
6. **搜索是子串匹配**，不是语义检索；40 条量级够用。
