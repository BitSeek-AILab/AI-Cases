## 2. 照做（三阶段）

### 阶段1 · 数据与结构设计

- 先把"老板会问哪几句"翻译成 6 个数字，**再**按 `choosing-a-form.md` 定形态（KPI → stat tile；趋势 → 折线；渠道量级 → 条形；品类占比 → 堆叠条；40 个 SKU 都要有意义 → **表格**）。详见 `讲课大纲.md` 第 1、2 段。
- 定数据模型：**一张 SKU × 天的事实表（2400 行）**，所有视图由它聚合 → "渠道合计 == 品类合计 == 总 GMV"是**结构上成立**的，不靠事后对账。
- **多写了一份 Python 参考实现**（`make_reference.py`）：把 `mulberry32` 精确移植到 Python，并**先验证一致性**（seed=20261012 前 6 个输出逐位相同），再生成对照数据集 + **逐行 SHA-256**。
  - 移植时踩到的坑：JS 的 `t = t + Math.imul(...) ^ t` 实际是 `(t + imul) ^ t`（`+` 优先于 `^`），我第一次读成了 `t + (imul ^ t)`，结果两边完全不同；改过来才逐位一致。
  - 另一个刻意规避的坑：**舍入**。Python `round()` 是银行家舍入、JS `Math.round()` 是 half-up，直接照搬会随机差 1 元 → 两边统一 `floor(x + 0.5)`。
- 实测输出：2400 行 / 逐行 SHA-256 `e06a5159…` / 非法行 0 / 周末·工作日 = **1.209** / 国庆·其余 = **1.583** / 三个切片口径三方一致。
- **顺手拿到一个好素材**：近 7 天环比 **−12.69%** 是数据自己长出来的（它的"上期"正好压着 10-01~10-03 国庆促销），不是调出来的 —— 正好用来演示"delta 颜色 = 方向 × 好坏"。

### 阶段2 · 单文件实现

- 结构选择：**一个连续的"交班台单面"**（发丝线分区），**不是卡片墙**——这是 `frontend-design` 要求的那"一处可说明的审美风险"。
- 签名元素：**hero 读数带**（hero 数字 + 本期/上期配对 + 30 点净销售额 sparkline 丝带压在同一条发丝线上）。
- 三张图全部**手绘内联 SVG**（不引任何图表库），逐条执行 dataviz 的 mark 规格：条形 ≤24px、数据端 4px 圆角、折线 2px、端点 r4.5 + 2px 面色环、**2px 面色间隙**（不是描边）、网格实线、**只标端点**、≥2 系列必有图例、**不给每点标数**。
- 交互：十字准线 + 读数窗（一次列全本期/上期/环比）、键盘 ←/→/Home/End 读数、条形/堆叠段可聚焦、表头排序（`aria-sort`）、品类 chip × 渠道下拉可叠加、搜索、空状态、深浅主题。
- **踩了 6 个坑，全部留痕在 `阶段2_单文件实现/阶段记录.md`**：① 局部 `const H` 遮住建节点助手 `H`（TDZ）导致整页半白；② ribbon/sparkline 误喂 60 天（前 30 天是 0，图上出现假平线）；③ 读数窗残留 left 把页面撑出横向溢出，而 `.console{overflow:hidden}` 一直在遮；④ x 轴日期标签碰撞；⑤ 页脚残留 Markdown 星号；⑥ 核验脚本自己的两个"假失败"（相对路径拼出非法 URL、点不到折叠线以下元素）。
- **②和④是"看图"看出来的，脚本查不出**——这是本案例最值钱的一条经验。

### 阶段3 · 功能与视觉核验

- 真开 headless Chrome + CDP（零第三方依赖），**82 项检查全过，页面 JS 错误 0**。
- 三条让结论可信的做法：**跨语言哈希**（页面 JS 生成 == Python 参考，逐字节）／**几何独立复算**（核验脚本自己实现 niceMax 与 Y()，与渲染的 `d` 比对，最大偏差 0.0050px）／**手机严格判据**（摘掉 `overflow-x` 与 `.console` 的 `overflow:hidden` 之后再量，且断言 `innerWidth` 严格相等）。
- 调色板：跑 dataviz 校验器存证 —— light 5 槽全 PASS（相邻 CVD ΔE 9.1 / 常人 19.6），**1 个 WARN**（3 个浅槽对底色 <3:1 → relief 义务）；dark 全 PASS。
- 逐张看了 11 张截图，**看出并修掉 4 个问题**（含上面 ②④⑤，以及可聚焦 SVG 上的 UA 默认黑框）。
- **磁盘纪律实际踩到并修正**：第一版 `cleanup()` 在 kill 之后立刻 `rmSync`，句柄未释放 → 静默失败，9 次运行留下 **273 MB** 临时 profile。改成 `kill → 每 250ms 重试删（最多 3 秒）→ 失败则打印警告`，并在启动时清掉自己的历史残留（跳过本次在用的那个）。修完实测残留 **0**。

- `自检表.md` 对照 `任务卡.md` 验收点 A/B/C/D 逐条打勾（依据是实测输出与截图，不是读代码推断）。

- **审查结论：通过（准予交付）**。审查方的最关键理由是"每一项红线都被我用独立复算的真值实测过，全部对上"：其自写生成器的行哈希与页面**逐字节一致**，7/14/30 天三切片的 hero / 6 KPI / 渠道 / 品类 / 排序 / 筛选都与其独立真值逐位相同；双方 md5 清单**逐项相同**（证明看的是同一批文件）。
- **修订轮**（3 条非阻断意见，全部已改并重跑）：① **折线端点直标重叠**（它实测 `本期` 与 `22.1万` 相交 22×10px —— 这是**我自检没覆盖的维度**：我只数了"4 个文本"，没量重叠）→ 改为按端点间距自适应的直标策略，并补上"包围盒交集必须为 0"的检查；② **深色截图名实不符** → 顺带查出更深一层原因：**本机系统偏好是深色**，页面没显式钉主题 → 同一批截图**深浅混着出**；改法是把主题钉住、截图名带 `-light`/`-dark`、`shot()` 打印主题、截图前断言读数窗已收起；③ **320px 副标题把"上期"折成两行** → 用 `nowrap` 段包住。顺手清掉两处死代码。
- **这三条的共同教训**：核验项的**数量**够了，但**维度**不够 —— B1 是"数了数量、没量重叠"，B2 是"证据没有自描述"，B4 是"只测了不横滚、没看断行"。修订轮补的正是这三个维度。
- **修订后重跑：82 / 82 通过，页面 JS 错误 0**（项数由 79 → 82，因为为这三条各补了会复现它们的检查）。
