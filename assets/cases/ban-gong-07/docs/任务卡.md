## 归档规则（本案例的核心）

```
归档路径 = 归档后_下载夹/{修改日期 YYYY-MM}/{类型}/{原文件名}
```

- **日期取"修改日期"（mtime），不取文件名**——因为下载的文件名常带**别人给的日期**，未必是下载/整理的日期（见痛点卡第 1 条陷阱）。手册写的是"按日期分类"，落地口径 = **文件系统记录的修改日期**（可复核、不依赖命名习惯）。
- **类型映射**（扩展名 → 类型）：

  | 类型 | 扩展名 |
  |---|---|
  | 文档 | doc/docx/pdf/txt/md/rtf |
  | 表格 | xls/xlsx/csv |
  | 图片 | png/jpg/jpeg/gif/webp/bmp |
  | 压缩包 | zip/rar/7z/tar/gz |
  | 音视频 | mp3/mp4/wav/mov/avi/mkv |
  | 程序 | exe/msi/bat |
  | **其他** | 无扩展名 / 未识别（**不丢、不报错**） |

- **同名不覆盖**：目标目录已存在同名文件时，自动追加序号 `(2)`、`(3)`……**绝不覆盖**。

> 手册场景为"Downloads 文件夹"。真实情况是命名无规律、**会有子目录、还会同名**。本素材刻意做成"文件名日期会骗人 + 子目录同名 + 无扩展名 + 0 字节"，取归属必须**看文件系统修改日期**，同名必须**加序号不覆盖**——这正是手工最容易归错、覆盖的地方。
>
> **为什么放子目录制造同名：** 同一个文件夹里不可能有两个同名文件；真实 Downloads 常带子文件夹（如"旧下载"），跨目录同名是真实存在的冲突来源。脚本必须**递归扫描**并对撞名文件加序号。

## 验收点（自检表逐条对应）

1. 5 类交付物真实落盘、能打开（目录树 + 文件可开；xlsx 可开；md/txt 可读）——**不许只描述不产出**
2. 归档脚本 `归档下载夹.py` **一条命令跑完**：扫下载夹 → 按 `年-月/类型` 移动 → 出对照表/清单/日志
3. 归档后文件总数 = 归档前（**17 = 17**，不丢不重，含子目录递归扫描）
4. 日期口径**取修改日期**：`季度报表_20260715.pdf` 必须落到 **`2026-09/文档/`**（**不是** `2026-07`）
5. 同名文件**不覆盖**：顶层 `report.pdf` 与 `旧下载/report.pdf` 均映射到 `2026-10/文档/`，须**一个保留原名、另一个加序号**（如 `report__2.pdf`），**两份都在**（`report.pdf` + `report__2.pdf`，内容/大小可区分）
6. 无扩展名 / 0 字节文件归入"其他"，**不丢、不崩**
7. 对照表与归档目录**逐项一致**（原名/修改日期/年-月/类型/新路径/大小）
8. 提供 `--dry-run` **干跑**演示（不移动仅预览归属），并留其输出
9. 按手册步骤顺序执行，未跳步、未擅自增加手册没要求的产物形态（不做 PPT / 不做交互页 / 不做定时任务）
10. 【替代】标注齐全（WorkBuddy 内置文件整理 → Python `os`/`shutil`；手册"图片" → 泛化为"所有类型"并按日期+类型分层）

## 明确的边界（不做的事）

- 不做"定时归档"（那是**办公-05** 的定时主题，本案例只做"跑一次"的归档脚本）
- **不真删任何文件**（只移动，且默认落到 `最终产物/`，不碰用户真实下载夹）
- 不搬运本机真实下载文件夹（用**自造等价素材**落 `输入素材/`，路径可由脚本参数替换）
- 手册原句只说"图片"，本案例**按任务要求泛化为"所有类型"**（日期+类型双层），并在过程记录标注该泛化理由
