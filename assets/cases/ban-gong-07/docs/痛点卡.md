## 二、痛点主体（【补全】）

**谁：** 任何用电脑办公的人（本案例取"下载夹堆了半年的职场人小王"）。

**真实的"下载夹"场景：**
Downloads 文件夹是全电脑**唯一一个"只进不出"**的地方——下载的东西默认都落这儿，下载完就忘了。于是：

| 步骤 | 手工做法 | 代价 |
|---|---|---|
| 1. 找东西 | 在一堆文件里按文件名/时间翻 | 文件名千奇百怪，找上周下的那份要**翻半天** |
| 2. 判断归属 | 打开看是什么、属于哪类 | 一个个点开，**纯体力** |
| 3. 建目录 | 手动建 `2026-09/图片` 这样的文件夹 | 建错了还得改 |
| 4. 拖拽移动 | 把文件一个个拖进对应目录 | 拖 50 个就是拖 50 次，**还会拖错** |
| 5. 重名处理 | 同名文件互相覆盖 / 系统提示"是否替换" | **一个手滑就覆盖掉一份** |

**旧做法的代价：** 几百个文件整理一次 **半小时**；而且**过两周又乱**——因为"下载 → 堆着 → 想起来才整理"这个循环没变。

**更本质的一点：** 这件事真正的难点**不是"分类"，是"分类的依据会被文件名骗"**——下载的文件名经常带着**别人给的名字**（如 `报表_20260715.pdf` 其实是 9 月才下载的），**文件名里的日期 ≠ 文件的修改日期**。按文件名分类会把同一批文件拆散到错误的月份。

**想要的目标：** 把**一整个乱下载夹**丢进去，直接得到 **① 按 `年-月/类型/` 分好层的目录结构 ② 一张"归档前 → 归档后"对照表**，且**同名文件不覆盖**。不是"学会写 Python 遍历/移动文件"，是"**下载夹一键变整齐、且能倒查每个文件去哪了**"。

**【补全】为什么值得解决：** 这件事的价值在"**它是可反复执行的**"。手工整理做得再好，也只是"这次整齐了"；只要"下载 → 堆着"的循环还在，两周后就白干。把规则固化成一个脚本，**以后每次想起来跑一下，几十秒回到整齐状态**；对照表留下"每个文件从哪来、到哪去"的痕迹，**万一归错可倒查**。这才是"自动化归档"相对于"手工整理一次"的真正增量。

## 三、价值归类

**目标导向 ✅**

要解决的是"**下载夹一键整齐、且找得到、不覆盖**"这个业务目标。
反面想想就清楚——如果只做成"教你写一段 `os`/`shutil` 遍历移动的代码"，那是**工具理性**（注意力放在手段"写脚本"上）；本案例要让学员只交代"**把下载夹按日期分类整理好**"，由 Agent 负责手段（扫文件夹 / 定规则 / 移动 / 留痕 / 防覆盖）。本卡不通过"只讲 shutil.move 语法"的写法。

## 四、本案例的"人工易错点"（复刻时特意做进素材，用来验证痛点是真的）

复刻时把下面几条做进输入素材，让"手工很痛"变成可验证的事实：

1. **文件名里的日期 ≠ 修改日期（最大陷阱）**：如 `季度报表_20260715.pdf` 的**修改日期其实是 2026-09-18**（9 月才下载的）。**按文件名分类 → 进错月份；按修改日期分类 → 正确。**
2. **同名文件**：下载夹里出现两个 `安装包.exe` / `report.pdf`——手工会**提示覆盖或手滑覆盖**；脚本必须**自动加序号不覆盖**。
3. **无扩展名文件**：如 `下载` （没有后缀）——类型无法从扩展名判断 → 归入"其他"，**不丢、不报错**。
4. **0 字节文件**：下载中断留下的空文件——也要被正常归档，**不能因为读不了而崩**。
5. **长中文名 / 特殊字符**：如 `2026年第三季度经营分析报告（终版）.xlsx`——手工重命名/移动容易出错。
6. **跨月**：素材覆盖 2026-08 / 09 / 10 三个月的修改日期 → 验证"按年-月分层"是对的。

> 这几条不是"加戏"，是把手册那句"智能扫描杂乱的下载文件夹，按日期规则自动分类归档"里**没有写出来的辛苦**还原成可验证的素材。不做进素材，就没法证明"手工真的会归错、会覆盖"。
