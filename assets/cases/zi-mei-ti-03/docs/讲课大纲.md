# 讲课大纲 · 自媒体-03 周报/长文 → 小红书风格改写

> 本案例是"领域二 · 自媒体"的**下游案例**，教学主线 = **报告味的病根在结构，不在词**。
> 手册只给了一句执行效果（M2 案例 11），下面把它拆成可讲的 4 幕 + 1 个"坑"。

---

## 教学主线（一句话）
**把周报改成小红书，"术语换口语"只是表面，"换视角 + 拆结构"才是本质。**
手册的执行效果里藏着三小步——**识别结构 / 换口语 / 加 emoji 标签**——最容易被跳过、又最决定成败的，是第一步。

---

## 四幕结构

### 第 1 幕 · 提需求（对应 M2 案例 11 原文）
- 讲师口播：运营者手里有一份**内部周报**，想搬到小红书发，@AI 一句话——
  **「把这份周报改写成小红书风格」**。
- 落点：**这是最容易一句话交代、也最容易一句话翻车的任务。**

### 第 2 幕 · 翻车现场（对应"改完还是报告味"的痛点）★关键
- 讲师展示**错误示范**（本案例实测对比，见 `阶段1_结构识别与改写/产物/改写前后对照.md` 的"坏例"）：
  把整份周报丢给 AI 说"改成小红书风格" → 得到一篇**"周报 emoji 版"**：
  - 术语是换了（"用户"→"宝子"），
  - **但骨架没动**：还是"本周数据 / 环比 +52.1% / 阶段性结论"的汇报骨架。
- **教学点**：**报告味的病根是"指标视角"这个结构，不是那些词。** 只做同义词替换 = 换汤不换药。
- 提问设计：*读者关心你的"涨粉 1482"吗？他关心的是你能给他什么。*

### 第 3 幕 · 识别结构（对应 M2 案例 11 第一步"识别原文逻辑结构"）★主线
- 演示：把周报**拆开**，逐段标处置（保留 / 删除 / 改写）：
  | 周报段落 | 处置 | 为什么 |
  |---|---|---|
  | 涨粉 1482 / 收藏率 118% | **删** | 读者视角无关 |
  | 7 个工具实测表 | **改写**（抽成"留下 3 个"的故事） | 这才是读者要的 |
  | 淘汰共性原因 | **保留**（金句） | "看似省事、实则增加返工" |
  | 内部原则 | **保留**（观点） | "能看过程、可接管" |
  | 下周计划 | **删** | 内部事务 |
- **教学点**：**改写的核心动作是"换视角"**——从"我这周干了啥"→"这对你有什么用"。

### 第 4 幕 · 重写成篇（对应 M2 案例 11 第二、三步）
- 按 **自媒体-02 的爆文结构模板**重写：标题公式（身份+结果）+ 开头钩子（结果前置）+ 骨架（对比类：留 vs 淘汰）+ emoji 锚点 + 分层标签。
- 配图：按 `guizang-social-card-skill` **品类路由**（职场类 → Swiss × IKB）出封面卡 + 内页 shot list。
- 收束（回扣 M3）：**"识别结构 + 换口语 + 排版"是重复劳动交给 AI；"这条对外讲不讲、讲哪个点"是创意判断，留给自己。**
