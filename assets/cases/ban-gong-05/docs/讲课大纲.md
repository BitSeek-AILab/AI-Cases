# 讲课大纲 · 办公-05 定时自动化：每天 9 点汇总周报并发送

> 手册本案例只有一句话提示词，没有展开讲法。本大纲按《子Agent执行规范》要求，把"案例如何展开"补出来（标注【补全】）。

---

## 一句话定位

**学员带走的能力：** 把"每周五要交一份团队周报汇总"这件**周期性、无难度、但会忘**的事，变成一条"**到点自己会跑**"的链路。
**不讲的东西：** 不讲 schtasks 参数手册、不讲 Windows 任务计划程序 GUI 怎么点、不讲 Python 怎么读 Word。学员不需要会，也不该会。

---

## 开场（3 分钟）：先制造痛，再给答案

【补全】开场三选一，本案例用"现场还原每周五下午"。

**做法：** 现场打开 `输入素材/` 文件夹，让学员看见里面 5 份名字各不相同的成员周报：
`张三周报.docx`、`周报-李四-0807.docx`、`王五 周报（第32周）.docx`、`钱七-周报-0807.docx`、`孙八_工作总结.docx`。

**关键提问（停顿，等学员答）：**
> "团队 6 个人，你手上只有 5 份。**你怎么知道缺的是谁？**"

引导学员自己说出：**光看文件名根本数不清**——得对着名单一个个核，或者干脆凭印象。

**收口：** "'催收、数齐、逐份抄录、套格式、转 PDF、发群'，1 到 2 小时，**每周五重来一次**。而且更麻烦的是——**少收一份、忘了发，都不会报错，是被上级催了才知道**。这就是今天要解决的问题。"

---

## 主体（20 分钟）：走一遍真实链路

### 第 1 步 · 一句提示词启动（1 分钟）

念手册原句：

> **每天9点自动汇总D盘「周报」文件夹内Word文档，转PDF并按'日报_YYYYMMDD'命名，发送至企业微信「行政群」**

强调：**不需要**先说"先遍历文件夹、再逐个读、再合并、再导出、再调接口"。一句话，Agent 自己拆步骤，最后交出**汇总好的文件 + 一个到点会跑的定时装置**。

> 【补全】点一句手册用词的不严谨：手册把"周报文件夹"的产物叫"**日报**\_YYYYMMDD"。复刻时按业务实际改成 **`团队周报汇总_{YYYYMMDD}`**——**命名规则要贴合真实交付对象，而不是照抄一个自相矛盾的名字。**

### 第 2 步 · 清点 + 读出缺口（6 分钟）：讲"汇总前先对数"

展示 Agent 不是"能读多少读多少"，而是**先清点、再报缺口**：

| 报告人 | 文件 | 是否收到 |
|---|---|---|
| 张三 | `张三周报.docx` | ✅ |
| 李四 | `周报-李四-0807.docx` | ✅ |
| 王五 | `王五 周报（第32周）.docx` | ✅ |
| **赵六** | —（无） | ❌ **未交** |
| 钱七 | `钱七-周报-0807.docx` | ✅ |
| 孙八 | `孙八_工作总结.docx` | ✅ |

**关键提问（本案例最高价值的一问）：**
> "汇总的时候，赵六没交。汇总文档里要不要提他？"

学员大概率会答"没交就不提了"。
**答案：必须显式写"本周收到 5/6，赵六未交"。** ——因为**汇总文档的价值有一半在"它是一份台账"**：上级看的是"这周团队交付了什么"，也看"**团队是不是每个人都交了**"。静默按 5 份汇总，等于把一个管理问题藏起来了。

**这一步的板书金句：** "**汇总不是"把有的话拼起来"，是先对数、再报缺口。**"

### 第 3 步 · 汇总成文（5 分钟）：讲"统一格式"

Agent 逐份读内容，抽出每个人的"本周工作 / 关键数据 / 下周计划"，按**统一结构**拼成一份《团队周报汇总》，并给出"本周概览 / 待办与风险"两节。

**关键提问：**
> "每个人周报格式都不一样，Agent 怎么知道哪段是'要点'？"

答：**靠字段而不是靠格式**——脚本抓"本周工作""下周计划"这类**栏目名**，栏目在就抽，不在就标"（未填）"。**格式千变万化，语义是稳定的。**

### 第 4 步 · 转 PDF + 按日期命名 + 定时（5 分钟）：讲"从一次到每天"

1. **转 PDF 命名**：`团队周报汇总_20260807.pdf`——日期取**报告周期的星期五**，规则固定、可复核。
2. **定时**：手册要"每天 9 点"，落地就是一条 `schtasks` 命令（现场展示命令全文与逐字解释）。

**关键提问：**
> "定时任务注册了，就一定安全吗？"

答：**不一定**——所以脚本要**能重复跑且不重复累加**（每次重新生成，不往旧文件里追加）；**文件路径要参数化**，换机器、换目录不改逻辑。**定时的前提是"这件事本身是可重复的、幂等的"。**

> 【补全】本机无真实定时环境 → **只输出命令、不实际注册**（`schtasks /create` 会改本机系统状态）。同时坦白："注册这一步，在你自己的电脑上跑一次那条命令就完成了。"

### 第 5 步 · 发送（3 分钟）：讲"最后一公里怎么落地"

手册要"发送至企业微信「行政群」"。本机**无企业微信凭证** → 产出**可发送的物料**：邮件草稿 + 企业微信群消息 JSON payload + 发送说明。

**关键提问：**
> "既然发不出去，为什么还要做这一步？"

答：**因为"发送"是一次性配置**——把草稿、payload、目标群名准备好，接入一次接口之后，**每天自动发**就成立了。**功能上差一步，但差的是"再接一个通道"，不是"整件事没做"。**

## 收尾（7 分钟）：从"每周五熬夜"到"到点自己发生"

### 对比表（板书/投屏）

| | 手工 | 本次链路 |
|---|---|---|
| 催收 | 群里喊 + 挨个私聊 | 到点自动扫文件夹 |
| 数齐/缺谁 | 对着名单一个个核 | **台账自动报缺口** |
| 汇总 | 逐份打开抄录（1 小时） | 脚本逐份读、统一结构成文 |
| 套格式 | 手动统一 | 固定模板 |
| 转 PDF + 命名 | 手动另存、手工改名 | 一条命令，规则固定 |
| 发群 | 手动发，易忘 | **模拟发送物料已备好** |
| **耗时** | **1–2 小时 / 每周** | **分钟级（且可无人运行）** |
| **下周五** | **再来一遍** | **到点自己发生** |

### 收束提问（回扣痛点卡）

> "今天真正省下来的，是那 1–2 小时吗？"

引导到正确答案：**省下来的是"靠人记得"，和"少收一份、忘了发却没人报错"的风险。**

### 留给学员的一句话

> "你不需要会写计划任务。你需要会**说清楚规则**（什么时候、扫哪个文件夹、汇总成什么、发给谁），以及**看得懂台账对不对**。"

---

## 板书/PPT 要点（备查）

1. 一个动作：扫文件夹 → 逐份读 → 汇总成文 → 转 PDF 命名 → 送到位（数量多少都一样）
2. 一个规则：`团队周报汇总_{报告周期星期五}.pdf`
3. 一个缺口：**收报要报缺口**（5/6，赵六未交），不许静默
4. 一条留痕：`schtasks` 命令 + 卸载命令 + **未注册声明**
5. 一条边界：发送是"备好物料 + 接一次通道"，不是"没做"
