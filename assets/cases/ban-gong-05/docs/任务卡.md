## 命名规则（本案例的核心之一）

```
汇总文件名 = 团队周报汇总_{报告周期星期五 YYYYMMDD}.docx / .md / .pdf
```

- 手册原句写的是 `日报_YYYYMMDD`，但本案例的汇总对象是**周报**（手册同段把"周报文件夹"的产物叫"日报"是原文的不严谨处）→ 命名取 **`团队周报汇总_{YYYYMMDD}`**，日期取**报告周期的星期五**，并把与手册原写法的差异显式记录（见 `过程记录.md` 第 4 步）。

## 输入素材

`输入素材/`（**5 份**成员周报，团队共 **6 人**，缺 1 份 → 制造"收报缺口"）：

| 原文件名 | 报告人 | 报告周期 | 说明 |
|---|---|---|---|
| `张三周报.docx` | 张三 | 2026-08-03 ~ 08-07 | 名字不带日期 |
| `周报-李四-0807.docx` | 李四 | 2026-08-03 ~ 08-07 | 名字带日期 |
| `王五 周报（第32周）.docx` | 王五 | 2026-08-03 ~ 08-07 | 名字写的是"第32周"，不带日期 |
| `赵六_未交`（**无文件**） | 赵六 | — | ⚠ **缺口**：本周没交，汇总须显式标出 |
| `钱七-周报-0807.docx` | 钱七 | 2026-08-03 ~ 08-07 | 名字带日期 |
| `孙八_工作总结.docx` | 孙八 | 2026-08-03 ~ 08-07 | 名字叫"工作总结"，不带日期 |

> 手册场景为"D盘周报文件夹内 Word 文档"。真实情况是命名不规范、**还会缺人**。本素材刻意做成"命名混乱 + 5/6 收报"，取数与汇总必须逐份读内容、并显式报缺口——这正是手工最容易漏的地方。

## 验收点（自检表逐条对应）

1. 7 类交付物真实落盘、能打开（docx/md/pdf 可开可读；xlsx 可开；json 可解析）——**不许只描述不产出**
2. 汇总脚本 `汇总周报.py` **一条命令跑完整链路**（清点→汇总→转 PDF→命名），输出到指定目录
3. 汇总 **含全部 5 份成员要点**（张三/李四/王五/钱七/孙八），**不多不少**
4. 收报台账 **显式指出缺口**："收到 5 / 6 份，**赵六 未交**"——不静默按 5 份汇总
5. 命名取自**报告周期星期五**：产出 `团队周报汇总_20260807.*`（日期可复核）
6. PDF 内容与 docx 一致（回读 PDF 文本抽查关键成员名与缺口句）
7. 定时任务：给出 `schtasks` **完整可复现命令 + 解释 + 卸载命令**，且**显式声明本机未实际注册**（不谎报"已定时"）
8. 发送：给出**模拟发送物料**（草稿 + payload + 说明），并写明"本机无企业微信凭证，未真实发送"的平台边界
9. 按手册步骤顺序执行，未跳步、未擅自增加手册没要求的产物形态（不做 PPT / 不做交互页）
10. 【替代】标注齐全（无真实定时环境 → schtasks 演示不注册；无企业微信凭证 → 模拟发送物料；WorkBuddy 插件 → docx/xlsx/pdf skill + Python 脚本）

---

## 明确的边界（不做的事）

- **不实际注册计划任务**（`schtasks /create` 会改本机系统状态）——只输出命令并解释，**显式声明未注册**
- **不真实发送到企业微信**（本机无该凭证/接口）——产出可发送的物料 + 平台边界说明
- 不搬运真实 D 盘文件夹（本机无该路径；用**自造等价素材**落 `输入素材/`，路径可由脚本参数替换）
- 不做"云定时/推送"（WorkBuddy 云端定时任务属平台能力，本机无；用**本地 schtasks + 脚本**等价替代）
