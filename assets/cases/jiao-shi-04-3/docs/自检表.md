**通过项（我实测确认的）**
- 单文件、离线零依赖：外链 `link/script[src]/img` = 0，CSS 内 `http(s)` 出现 0 次；file:// 直开正常。
- 拖动真的能拖：CDP 真实鼠标拖动后 `placed=[0,1]`；算式行变为 `1/3+1/4=4/12+3/12=7/12`；条宽 4/12 与 3/12（`33.33%`/`25%`）；结果行 4/12 + 3/12 共 7 格。

- 逐题点选：7 题全部"错项→`fb show bad` + 具体错因；正确项→`fb show ok` + 正向文案 + 口诀"，得分 0→7；

**发现的问题**
1. **【必须修·中】Q4 选项 D（1/3）的错因文案算错，且与同题 B 的错因自相矛盾。**
   - 位置：`最终产物/分数加减法_互动练习.html` 第 402 行（Q4 第 4 个选项的 `why`）；同源错误见 `阶段1_题型与交互设计/设计稿.md` 第 93 行。
   - 现状：点 D(1/3) 弹出「✘ 沿着错的做法再约分，还是错的。**1/3 是把错误过程的 3/6 约出来的**；错在没把 2/3 通分成 4/6 那一步。」
   - 问题：`3/6` 约分得 `1/2`，不是 `1/3`。同一题的 B(3/6) 错因却写着「3/6 还得约成 **1/2**」——两条文案互相打架，且前者把一句错误算术当成事实讲给学生。
   - 对照：同模板在 Q2-D（5/10→1/2）、Q3-D（6/8→3/4）都是对的，唯 Q4-D 把 `3/6` 错配成 `1/3`（若要保留此干扰项，应改为「2/6 约出来的」之类）。
   - 命中 reviewer-brief 第六节打回条款「答案或错因出现数学错误」。
2. **【建议修·中】通分实验室：棋盘内的等分竖线与分数条、刻度尺没有对齐。**
   - 位置：`最终产物/分数加减法_互动练习.html` 第 134 行 `.board-grid{ … left:78px; … }`（78px 与左侧标签列同宽，疑为复制错位）。
   - 实测（像素级）：泳道左 = 142px，条/刻度尺格宽 = 106.3px；而棋盘内竖线实际落在 x=221、321、421…（起点相对泳道左偏 **+79px**，间距 **100.0px**）。即竖线整体右移最多约 **0.74 格**、格宽也比条窄 6px。
   - 后果：蓝条（4/12，右缘 566px）结束时并不落在任何一条竖线上，而是停在两条竖线中间；学生若按棋盘里画的格子数，会数成"没盖满 4 格"。刻度尺上的 `1/12` 标签与条是对齐的，所以算理不错，但**棋盘内竖线这一主视觉与结论不符**，削弱了本案例的核心卖点「看见它正好盖住 4 格」。
   - 修法：把 `.board-grid` 的 `left:78px` 改为 `left:0`（改后竖线起点与泳道左对齐、格宽 106.3px，与条一致）。
3. **【轻微·可选】符号字形回退**：反馈文案的 `✘` 在无头 Chrome 下回退成普通 "X"（`✔` 正常）。不影响判读，仅美观。
   → **【已由父 Agent 处理，见文末】** 改为中国课堂惯用的批改符号 `×` / `√`，同时与案例04-1 的记号统一。**这一条现已不是遗留项。**
4. **【记录类】** 案例自带的 `联调记录.md` 步骤 4 与 `自检表.md` 第 30 行称"截图 02 见蓝条盖 4 格""版式不破"，但上述竖线错位在同一张截图里就存在，**目视环节未发现**；自检表第 34 行"每个错选项的错因说明与错法一致 = ✅"也未发现 Q4-D 的算错。这两条自检结论应下调。
