**两处手册错的详情：**

1. **"400分以上6人" → 实为 7 人。** 数一遍就知道：419、411、411、404、404、403、401。手册漏数了 1 人。影响：报告里"高分段人数"的说法会偏小。
2. **"严重偏科型…7人" → 按规则实为 27 人。** 手册在同一小节给出的判定规则是"最高科和最低科分差超过30分"；严格按此规则，40 人中有 **27 人** 分差 > 30。手册点名的 蒋天磊(45)、王浩然(53)、谢婉婷(44) 都在名单里——**名单对、人数错**。影响：若照抄"7人"，会漏掉 20 个需要干预的学生，这是最严重的一处。

### 第 2 重：产物自查（重开文件 + 第三方复算）

`_work/verify_xlsx.py` 做三件事：
1. **重开产物**，确认 8 个页签在、公式字符串已正确写入（例：`各科统计!B2 = =ROUND(AVERAGE('学生明细'!C$2:C$41),1)`）。
2. **从源 xlsx 独立重算一遍**（不复用 analysis.json），与产物"关键数字核对"页逐项比对 → 五科平均分/及格率/优秀率**全部 OK**，总分行 OK。
3. **点行数**：总分前10名 10 行、后10名 10 行、偏科生 27 行、学生明细 40 行，全部符合预期。

输出：`RESULT: ALL OK`。

## 四、技术处理（skill 规则的落地与偏离）

1. **公式 vs 值**：`xlsx` skill 要求"用公式不用硬编码结果"。本案例照做——`各科统计`、`分数段分布`、名单页的总分列都用 Excel 公式引用 `学生明细` 页。
   - ⚠ **坑3：本机没有 LibreOffice**（skill 的 `scripts/recalc.py` 依赖 `soffice`），无法在服务器侧把公式算出缓存值。若不处理，用非 Excel 的阅读器打开会看到空白。
   - **对策**：① 写入时设 `wb.calculation.fullCalcOnLoad = True`，Excel/WPS 打开即自动重算，看到的就是正确数字；② 单设 `关键数字核对` 页放**脚本独立复算的静态值**，任何阅读器都能直接看到正确数字，也正好充当"核一眼"的对照页。
2. **字体**：skill 要求 Arial/Times New Roman。因内容全为中文，Arial 无 CJK 字形、Excel 会回退，故改用 **微软雅黑**（专业中文无衬线）。**【偏离】**，理由：中文交付物的可读性优先。
3. **百分比存为分数**：及格率/优秀率存 `0.85` 用 `0.0%` 格式渲染成 `85.0%`（符合 skill"存为分数"的规定）。
4. **未用 `XLOOKUP/SORT/FILTER`** 等新版函数（skill 明确禁止）；排序、筛选全在 Python 侧完成再写入单元格。
