## 全流程踩到的坑（供后续案例复用）

### 坑 1 · 正则 `$` 默认只匹配"整串结尾"，不是"每行结尾"（本案例新踩）
- 抽「应聘岗位」时用 `(...)[:：]\s*([^\n]+?)(?:\s{2,}|$)`，因为 `full` 是 `\n` 连接的多行串，`$` 只在整串末尾命中 → 5 份全部抽空。
- **结论：多行文本里的"行尾"要么用 `re.M`（multiline），要么直接 `[^\n]+` 取到行尾。**

### 坑 2 · "工作年限"口径不显式化 = 不可复核
- 若不给口径（含不含首尾月、实习/空窗算不算），同一份简历能算出好几个数。
- **结论：凡涉及"人工会算错的量"，必须把口径写进任务卡 + 表格说明，让产物可复核。**

### 坑 3 · Excel 列宽不足会"看起来像数据错了"
- 首版列宽不够，导出预览时「计算机科学与技术」「人力资源专员 / HRBP」「邮箱」显示为截断，**单元格值其实是完整的**。
- **结论：交付表要看"渲染出来"的样子，不能只看单元格值。**

### 坑 4 · Excel COM 僵尸进程（沿用办公-01 结论）
- `render_preview.py` 用完 `Quit()`+释放引用+`CoUninitialize()`；跑完 `taskkill` 确认 EXCEL 退净。

### 坑 5 · 需 key 的 skill 要绕开（沿用环境备忘）
- `everything-to-markdown` 需 `MINERU_API_KEY`，本机未配置；简历是**原生 docx（非扫描件）**，直接 `docx` 读即可，无需 OCR/转 md。

### 坑 6 · 本机 Python 分裂成两个（沿用已跑案例结论）
- 一律用 `py -3`（`E:\miniconda3\python.exe`）。

### 坑 7 · vision MCP 401（沿用已跑案例结论）
- 表版式核对：Excel COM 导 PDF → `pymupdf` 渲染 PNG → 直接 Read 目视。

### 坑 8 · Markdown 加粗标记在 Excel 里不渲染（新踩，同办公-01 坑 2）
- 往单元格写"**仅为便于对照比较**"，`openpyxl` 按原样写入，Excel **不渲染 Markdown**，直接显示 `**…**` 星号。
- **结论：写进 docx/xlsx 的文案不要带 Markdown 标记；要强调就设字体加粗属性。**

```bash

```

## 规模可扩展性说明

手册场景是"分析这份简历"。**本案例脚本按"扫文件夹 → 逐份抽取 → 汇总"实现，不依赖文件数**——把素材从 5 份换成 50 份、500 份都能直接跑；字段与口径不变。这正是"招聘季天天要筛"痛点真正的解药所在。
