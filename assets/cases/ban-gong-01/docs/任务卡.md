## 输入素材

`输入素材/华南大区销售流水_20260928-20261011.xlsx`（单文件、单工作表"销售流水"）：

- 字段：**日期 / 门店 / 销售额(元) / 订单数**（客单价 = 销售额 ÷ 订单数，不在源表里，需算）
- 范围：**14 天 × 4 门店 = 56 行**，覆盖前一周（2026-09-28 ~ 10-04）与上周（2026-10-05 ~ 10-11）
- 4 门店：深圳福田旗舰店 / 深圳南山科技园店 / 广州天河店 / 东莞松山湖店

> 手册场景为"本地 Excel 或企业微信表格中提取数据"，真实情况是流水表里混着好几周数据。本素材刻意做成"两周混在一张表里"，取数必须按周切分——这正是手工最容易框错的地方。
> 手册提及"多个表格"；本案例按任务书要求用**一份合并流水表**作演示，脚本按"日期列"切周（不依赖文件数），加文件不改逻辑。

## 验收点（自检表逐条对应）

1. 3 类交付物真实落盘、能打开（docx 可开、pdf 可开、PNG 可查看）——**不许只描述不产出**
2. 上周（10-05~10-11）与 前一周（09-28~10-04）**按周正确切分**，行数为 28 + 28 = 56
3. 所有数字**由源素材真实计算**，无编造；每行 `销售额 = 订单数 × 客单价` 自洽
4. **环比数值与符号正确**：天河店为负（−12.13%），其余三家为正；报告与图表逐项一致
5. 大区综合客单价用**加权**（大区销售额 ÷ 大区订单数 = 311.56），非四店简单平均（297.50），并在报告中显式说明
6. 指出"各家店客单价都没变、大区客单价微降"的结构效应，结论有数据支撑
7. 图表数据与工作簿一致，且已渲染核对（无缺字、无重叠、无裁切；涨跌颜色语义正确）
8. 按手册步骤顺序执行，未跳步、未擅自增加手册没要求的产物形态（不额外做 PPT / 交互看板）

## 明确的边界（不做的事）

- 不做 PPT（手册原句只要"日报 + PDF"）
- 不做"自动发送到群"（手册写"发送至指定群组"，但本机无企业微信凭证、无法真发 → 产出**可直接发群的 PDF**，并在过程记录注明发送环节的边界）
- 不引入手册未提及的更长时间跨度数据（两周足够验证"取数按周切分"这个痛点）
