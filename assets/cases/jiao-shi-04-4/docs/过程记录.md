## 遇到的坑（全记录）

| # | 坑 | 现象 | 怎么发现 | 怎么解 |
|---|---|---|---|---|
| 1 | **画师环境完全不通** | `gpt-image` CLI 报 "could not find the gpt-image CLI backend" | 按 skill 文档执行 CLI 时的实测报错（这是"先试"的结果，不是假设） | 按规范第六节【替代】；替代方案避开手册自曝的乱码坑，并把 prompt 单独落盘以便日后接真画师 |
| 2 | **卡片版面溢出 262px** | 第一次出图"三个坑"被截断、课后一练与页脚完全不见 | 出图工装的版面体检：`contentBottom: 2182 > 1920`，`overflowCount: 20`；看图确认 | 30 处参数收紧 → `contentBottom: 1884, overflowCount: 0` |
| 3 | **收紧后页面偏空** | 页脚上方约 200px 无内容，观感松散 | 看第二轮出图 | 16 处参数回填（把空间还给可读性）→ 空白收窄到约 130px，平衡 |
| 4 | **把体检做成硬闸** | 若只打印警告，溢出图仍会被当成成品交付 | 意识到"排版糙"正是手册抱怨的坑 | `render_card.mjs` 改为**溢出即 `exit 3` 拒绝出图**，把审查配置里"内容被裁切→打回"这条变成程序化断言 |
| 5 | 手册的 3 个布局风格组合无人可选 | 本案例是该角色的扮演者，没有"用户"来选 | 读手册原文发现 Baoyu Infographic 会给 3 个选项 | 直接落定组合①（手册推荐项），并把三者取舍理由写进设计稿，等于把"选项"与"选择依据"一并留痕 |
| 6 | 通用信息图讲不清算理 | 手册的 Baoyu 路线是文字卡 + 图标 + 分栏，"分母不同 = 计数单位不同"用文字说不透 | 设计时发现 | 在设计稿里坚持插入 CSS 分数条图示，并写死三条几何判据；该判据后来成为审查项第 4 条 |
| 7 | **同一张卡上两种分数写法并存** | 分数条行标签与结论句用斜杠（`1/3`、`1/4 = 3/12`），算式区用竖式分数 | 看终版成品图时发现，五年级教材里分数永远是竖式 | 把行标签、结论句、小节标题、易错点卡的分数**全部改为竖式**（打磨 A）；因此 +29px 高度，触发一次溢出，已通过 gap/padding 收回 |
| 8 | **删除线横穿竖式分数** | 分数改竖式后，表示"错解"的 `line-through` 会横穿分子数字，放大核对时确认很脏 | 放大易错点区域看图 | 去掉删除线，改为「错解」/「正解」胶囊标签（打磨 B）。**副作用是更正**：脱离老师后"错解/正解"比"划掉"更自解释，正好服务形态四的硬约束 |

## 与手册预期的差异（汇总）

1. **Baoyu Infographic 与 baoyu-image-gen 本机都没有** → 设计师段用 prompt 模仿（附录B 指定的复刻方式），画师段用本机渲染链路。**均已标注【替代】及理由**，未假装出图。
2. **手册的内置引擎坑被反过来利用**：手册说内置引擎"文字容易乱码、排版糙"；本替代用真实字体 + 代码写死数字 + 程序化溢出断言，反而把这两个坑堵住了。
3. **手册未给卡片的逐步设计流程**（只给了主题与一句指令 + 一段交互记录）→ 本案例把 Baoyu Infographic 该做的四步显式补全并落盘，使复刻可被审查、可被迁移。
4. **卡片内容做了取舍**：手册说"把这一课的核心知识点做成一张知识卡片"，本案例明确**不把教案搬上卡**（教学目标、教学流程、课堂环节全部剔除），只留"学生会忘的"五块 —— 因为形态四的失败模式就是"做成一张什么都有的漂亮海报"。
5. **【补全】的形态四定位**：三种课堂形态的有效期都止于下课铃，形态四是唯一跨过下课铃、脱离老师与教室仍能工作的产物 —— 因此"适合手机"与"自解释"是它的硬约束，这也解释了本案例为何坚持保留分数条图示与错解/正解对照。
