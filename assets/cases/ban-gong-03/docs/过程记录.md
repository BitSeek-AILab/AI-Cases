- **错 1 · 比较句写反：** 初稿摘要写"南山 2 月跌幅小于福田"——核对后实际南山 −11.69% vs 福田 −10.68%，**南山跌得更深**。已改为准确表述。**这个错来自"体量大的店应该跌得少"的先验印象而非数据。**

> 两处错误同源：**数字算对了，不等于结论讲对了。** 这正是本案例痛点（"错的数据/错的结论看起来完全正常"）的现身说法。

## 第 6 步 · 公式重算【替代】

| 项 | 内容 |
|---|---|
| 做了什么 | 让 openpyxl 写出的公式获得缓存值 |

| 本机状况 | xlsx skill 的 `scripts/recalc.py` 依赖 LibreOffice，**本机未安装**（`C:\Program Files\LibreOffice\` 不存在，`soffice` 不在 PATH） |
| 【替代】方案 | 自写 `_脚本/recalc_excel.py`，走**本机 Excel COM**（`win32com`）：`DispatchEx('Excel.Application')` → `CalculateFullRebuild()` → `Save()` |
| 结果 | 重算成功。回读验证：合并明细合计 6,374,820 / 10,180 / 626.21、门店汇总 4 行 + 合计行、月度汇总 3 行 + 合计行——**全部有值且与 Python 计算值逐项一致** |

## 全流程踩到的坑（供后续案例复用）

### 坑 1 · 本机 Python 分裂成两个，用错一个就装不上库
- `python` → MSYS2 mingw64 Python 3.10.9，`pip install openpyxl pandas matplotlib` **编译依赖失败**；
- `py -3` → `E:\miniconda3\python.exe`，openpyxl / matplotlib / python-docx / numpy / pywin32 **都在**。
- **结论：本机一律用 `py -3`。** 且 xlsx skill 里"openpyxl/pandas/markitdown 已预装"的说明在本机 MSYS2 Python 下不成立。

### 坑 2 · 没有 LibreOffice
- xlsx skill 的 `recalc.py` 直接不可用。改用 Excel COM（本机装了 Office）。**没查清就照抄 skill 命令会白跑一轮。**

### 坑 3 · 中文路径 + Bash `cd` 失败
- Git Bash 在中文路径上 `cd` 报 `No such file or directory`（编码问题）。**改用 `py -3` 传绝对路径操作文件，不要用 Bash 的 `cd`/`ls` 处理这些中文路径。**

### 坑 4 · matplotlib 中文必须显式配
- 不设 `font.sans-serif=['Microsoft YaHei']` 且不设 `axes.unicode_minus=False`，会中文变方块、负号变乱码。**已确认 YaHei 覆盖 `▲▼`，无缺字。**

### 坑 5 · Word COM 导 PDF 的两种方式，一种出来读不了
- `Document.SaveAs(pdf, FileFormat=17)` 导出的 PDF，读取器报 **"password-protected"**；
- 改用 `ExportAsFixedFormat(OutputFileName=..., ExportFormat=17)` → 正常。
- **结论：Word COM 导 PDF 用 `ExportAsFixedFormat`。**

### 坑 6 · 视觉核对通道不通，需备两条替代
- `mcp__agent-vision__analyze_image` 返回 **401（`VISION_API_KEY` 无效）**。
- 替代路径：① 程序化捕 matplotlib 缺字警告；② Word 导 PDF → `pymupdf` 渲染 PNG 逐页目视；③ 图表 PNG 可直接查看（本次三张图都是直接看过的）。
- **结论：本机做视觉核对，走"直接查看 + 程序化检查"，不要依赖 vision MCP。**

### 坑 7 · 报告初稿出现一处"想当然"的错误（最有价值的一个坑）
- 详见第 5 步与阶段 3 记录：把"南山 2 月跌幅小于福田"写反了。
- **教训：报告里的每一句比较句都要回数据核对。** 这正是本案例要教的东西——数字错的时候，报表不会报错。
