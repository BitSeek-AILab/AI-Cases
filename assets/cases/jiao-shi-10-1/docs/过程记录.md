## 二、⚠ 关键证据：**"其余一个字不动"是逐字符证明的，不是目测的**

本案例唯一红线是"只动选中段"。为此做了**三重校验**（原始报告见 `阶段2_替换与校验/`）：

| 重 | 层面 | 判据 | 结果 |
|---|---|---|---|
| 1 | XML | 选中区之前 `[0:51518)`、之后 `[53769:97986)` 逐字符相同；差异区间 ⊂ 选中区；选中区**格式骨架**（剥离 `<w:t>`）逐字符相同；其余 21 个 zip 条目逐字节相同 | ✅ 全过 |
| 2 | 文本 | python-docx 重开两份：段落数 64=64、表格数 6=6、文本行 149=149、**文本行差异 3**、**表格单元格差异 0** | ✅ 全过 |
| 3 | 视觉 | Word COM 渲染 PDF → 110dpi PNG；页数 4=4；第 1 页 md5 完全相同；第 2 页差异处正是导入段；3/4 页为正常重排 | ✅ 版式未乱 |

> 报告结尾原文：`RESULT: ALL OK —— 除选中区外，document.xml 逐字符相同；其余 zip 条目逐字节相同`

## 三、技术处理（关键决策与坑）

### 决策：**不用 python-docx "重存"，改用 XML 字符区间替换**

python-docx 保存时会整份重排 XML（命名空间、属性顺序、序列化全部重写）。那样**无法证明**"其余一字未动"，只能靠目测。
本案例改为直接对 `word/document.xml` 做字符区间替换（新段落复用原件 `<w:pPr>`/`<w:rPr>`），才拿得到**逐字符相同**的硬证据。**这是本案例最重要的一个实现选择**，也是把 GUI 能力"等价复刻"成机器可验证动作的关键。

### 坑 1：校验判据第一版写错，误报 FAIL

第一版用"公共前缀长度 == 选中区起点"当通过条件 → 报 FAIL（51841 vs 51518）。
**根因**：选中区**首尾的 XML 骨架本身没变**（`<w:p><w:pPr>…` 与 `</w:p>` 新旧一致），所以公共前缀/后缀会**自然延伸进选中区内部**。
**改正**：判据换成"在选中区边界切开，区外必须逐字符相同"+"差异区间必须 ⊂ 选中区"。改后一次通过。

### 坑 2：PowerShell 5.1 按 ANSI 读 `.ps1`，中文注释导致语法错误

`render_docx_pdf.ps1` 首版带中文注释 → `Unexpected token ')'`。
**根因**：本机 PowerShell 5.1 对无 BOM 的 UTF-8 `.ps1` 按系统 ANSI 码页解析，中文注释被打乱并吞掉下一行。
**处置**：把该脚本改为**纯 ASCII 注释**；含中文的参数仍由命令行传入（命令行不受此限）。

### 坑 3：无 LibreOffice / 无 pandoc

`docx` skill 推荐的 `soffice` 渲染链不可用（【替代】）。改用 **Word COM（Office 16.0）** 导出 PDF + **`E:\texlive\2022\bin\win32\pdftoppm.exe`** 出 PNG。
（注：`pdftoppm` 不在 `E:\texlive\2022\bin\windows\`，在 `bin\win32\`。）

### 坑 4：python-pptx 装在用户 site-packages

用 `python -I`（隔离模式）时读不到 `C:\Users\l\AppData\Roaming\Python\Python310\site-packages`。
**处置**：脚本内显式 `sys.path.insert(0, ...)`。本案例只读 docx 不受影响，但案例10-3 需注意。

### 未踩但已规避：中文路径

Bash（Git Bash）对含中文的路径会乱码报错；本案例凡涉及中文路径一律走 PowerShell 或用引号包好的绝对路径。
