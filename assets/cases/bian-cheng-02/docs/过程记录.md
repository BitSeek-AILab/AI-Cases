### 2.1 返工 1：我的第一直觉被 `frontend-design` 打回

我的初稿视觉是"**暖米纸底 + 高对比衬线大标题 + 朱砂红强调**"。
`frontend-design` 的 SKILL.md 明确把这一套列为**当前 AI 生成设计的默认观感 (1)（warm cream ≈ `#F4F1EA` + high-contrast serif display + terracotta accent）**；
而"直角 + 细线栏"又撞默认 (3)；方向 B（近黑 + 酸绿）撞默认 (2)。
**两个方向都被否决**，重新选为 **Direction C：冷灰蓝纸 + 电紫单点 + mono/sans 双角色 + 测量刻度母题**。

> 这条返工**不是走流程**：它实际改掉了 **底色明度温度、标题字体族、强调色色相** 三件事。
> 记录在 `阶段2_参考拆解\产物\设计令牌卡.md` §二。

### 2.2 返工 2：参考站的深色底不能借

最初想"顺手把参考站的深色底也借了"。对照 M6 #38（`Change: Brand identity, colors, typography feeling…`）
与拆解表自己的"视觉整段换掉"承诺，判定**不可借**——深色 slate 是该站**最强的视觉身份**。
改为**明度基调反转**（浅色），确保两者"不会一眼相像"。

## 6. 坑与经验（给后续案例）

| # | 坑 | 经验 |
|---|---|---|
| 1 | **手册的"痛点"可能只是格式要求** | M6 是提示词库，痛点写的是"复刻类 prompt 应强调…"——**不是人的处境**。必须按 〇补节翻译成"谁、卡在哪、花多少代价"，并**全部标注【补全】**，不新增手册没有的事实 |
| 2 | **最容易翻车的是"我替产物吹牛"** | 文档里写"CSS + 内联 SVG"，产物里 `<svg>` 是 0 个。**凡是关于产物的声明（零位图/零外链/单一强调色），都要有机器读数背书**，不能靠作者自述 |
| 3 | **视觉方向的第一直觉往往就是 AI 默认观感** | `frontend-design` 直接把"暖米纸 + 衬线 + 朱砂"列为默认 (1)。**先查默认清单，再定方向**——否则"换成自己的视觉"会换成另一种模板脸 |
| 4 | **参考站最有辨识度的东西就是他最强的视觉身份** | 深色 slate 底不能借；借了就是"换皮不换视觉"，审查该打回 |
| 5 | **版权边界可以被机器验** | 把参考站的身份/文案串列成黑名单逐串扫页面全文——比"我觉得没抄"强得多，也让审查有据可依 |
| 6 | **没有公开地址的作品别做成链接** | 5 件作品是本地文件 → 做链接必然产生 `href="#"` 或假链接 → **宁可不放链接，也不放点不开的链接**（并把这句写进页脚） |
| 7 | **移动端导航用换行 chips，不用横向滚动条** | 编程-01 复盘里那条"元素内部横滑"的边界争议，本案例**直接从设计上消除**；`pre` 也用 `pre-wrap` 让内部也不横滚 |
| 8 | **Bash 中文路径** | 按 `环境限制备忘.md`，核验/替换一律走 **Node 脚本 + 绝对路径**（脚本文件用 Write 落 UTF-8），不在 bash 里拼中文路径 |
| 9 | **审查方查的，恰恰是我"随手写的统计数字"** | 复审方抓出的前两条都不是产物问题，而是**文档里的统计口径**（黑名单"14 串"实际 12 串、作品③"3 条意见"实际 4 条）。**凡是写进文档的计数（串数/条数/张数/字节/行数），都要回查源码或原始记录再写**，不能凭印象填 |
| 10 | **改完产物必须重截全部截图** | 只改 CSS 也会让旧截图失效（`04 边界` 改 2×2 后，旧的 bottom/fullpage 图与交付版不符）。并按 `运行日志.md` 坑12 的常设规矩，**对截图做 MD5 两两不同校验**（本次重复组 0） |
| 11 | **别在审稿人的记录上动手** | 修 md5/字节时用脚本全量替换，**误把审查方 D.4 表里"他当时测到的 md5"一起改掉了** —— 那会毁掉审计留痕。已还原，并立规矩：**审查方记录（D 节）保持原样，生产方的回应另起 E 节**，交付版指纹在 E 节说明 |
