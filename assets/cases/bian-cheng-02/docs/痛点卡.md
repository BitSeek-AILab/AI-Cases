## 1. 痛点原句（引用手册原文）

**出处 M6 · 格式要求 4（"参考复刻"这一类的总规定）**
> 「复刻类 prompt 应强调**借鉴布局、动效节奏、信息层级和设计系统**，**不复制受版权保护的素材、商标、图片和完整文案**。」

**出处 M4 · P14（怎么用参考，本案例的方法论原句）**
> 「不要只截图，要告诉 Codex 参考**哪里**：**01 结构 02 视觉 03 交互 04 改成自己的**（借方法，不搬运文案、商标、图片和整站代码。）」

**出处 M6 · #35 Recreate A Website From Screenshot（截图复刻类的原句）**
> 「Recreate the **layout, spacing, information hierarchy, interaction rhythm, and component behavior**.
> Replace copyrighted imagery with neutral placeholders or clearly marked replaceable assets.」
> （中文提示词）「上传截图后，让模型复刻布局和交互……可替换变量：截图、品牌、文案。」

**出处 M6 · #36 Analyze A URL And Rebuild The Pattern（URL 复刻类的原句）**
> 「Explain briefly **which patterns were borrowed and which content was changed**.」
> （中文提示词）「给模型一个参考 URL，先拆解再复刻为新品牌……Do not copy logos, images, icons, trademarked names, or exact copy.」

**出处 M6 · #69 Reference URL: Analyze And Rebuild（"最常用"条的验收原句）**
> 「Borrow **layout logic, pacing, interaction patterns, and design-system principles only**.
> Do not copy logos, imagery, trademarks, exact copy, proprietary illustrations, or protected assets.」
> **Deliver**：「A short note explaining **what patterns were borrowed, what was changed, and which assets are placeholders**.」

**【补全】痛点句（手册给的是"格式要求"，没说人的处境；按〇补节补全并标注）**

> 【补全】看到一个喜欢的网站想"照着做一个自己的"，**只能截图 + 口头描述**：
> 一句"参考这个站，帮我做一个差不多的"丢给 AI，出来的东西 **形似神不似**——该像的地方都不像，
> 不该像的地方（配色、字体、卡片）又照搬得一塌糊涂。
> 更麻烦的是**验收那一刻才炸**：做完发现**配色是人家品牌色、图是人家拍的、文案是人家写的**，
> **不敢用、不敢发、不敢交**。于是要么推倒重来（**又是几小时**），要么硬着头皮用（埋着版权雷）。
> 真正缺的不是"再截几张图"，而是"**把参考拆成结构 / 视觉 / 交互三段，再逐段换成自己内容**"的方法。

## 2. 痛点主体：谁

**有参考对象、想做出"自己的那一版"、但只会截图+口头描述的人**——
课上是零基础学员 / 个体创作者 / 接单的设计与运营。
（对应 `案例清单.md` 编程-02 的补全）"看到一个喜欢的网站想照着做一个自己的"。

## 3. 旧做法的代价（绑定时长 / 动作量）

- **只给截图，不给判断** → 模型只能猜：它不知道我**喜欢的是布局还是颜色**，于是**把能抄的都抄**（含商标位、品牌色、整卡片），
  该借的结构反而没借到 → **形似神不似**。
- **反复"再像一点"** → 一轮轮加截图、补形容词（"再高级一点""再大气一点"），**几小时过去**，改的都是表面，
  信息层级/交互节奏**一次都没被交代过**。
- **转折点在验收** → M6 #35/#69 的红线是"不复制受版权保护的素材"。**做完才发现抄了**：
  配色是对方品牌色、配图是对方的、文案逐句对应 → **授权不通过，前功尽弃**；删掉就散了架，不删就有风险。
- **返工成本全在后头**：**推倒重来 = 前面几小时归零**；**硬着头皮上 = 埋雷**。

## 4. 想要的目标：做到什么程度算"解决好"

拿到两样东西：
1. **一份《参考拆解表》**——参考 URL → **结构 / 视觉 / 交互**三段各写清"**借什么**"，再加一段"**换成自己的什么**"；
2. **一个用自己内容重建的单页 HTML**——**能双击打开、手机能读**，且能一句话说清
   "**我借了哪个方法、我换了哪些内容**"，**不含原站商标 / 图片 / 整站代码**。

## 5. 【补全】为什么值得解决

【补全】手册把它写成了"格式要求"（复刻类 prompt 应如何写），**没说"为什么这对使用者重要"**。补一句：
"参考"是**最高频的建站起点**（M4 P11 三种起点的第②种就是"参考链接"），也是**最容易翻车的那一种**——
翻车不在技术上（AI 完全能复刻），而在**边界上**：**借得太多是抄袭，借得太少是形似神不似**。
"**拆成三段再换自己内容**"恰恰是把这段模糊地带**变成可操作、可验收的动作**：
结构/视觉/交互三段**各借各的、各换各的**，逐段留痕 → 交付时能**指着段落说清借了什么、换了什么**。
这一步正是 Agent 能补上、而用户靠"再截几张图"永远补不上的部分。

## 6. 价值归类

- ✅ **目标导向**：用户真正要的是"**一个敢发出去的、自己的那一版网页**"（结果），不是"学会扒人家代码"（手段）。
- ⚠️ **需避免的工具理性陷阱**：继续堆截图、抠像素级还原度、研究"怎么把人家站整个爬下来"，
  而不是先回答"**我参考它哪一段（结构/视觉/交互），哪一段要换成我自己的**"。

## 7. 本案例复刻意愿（一句话）

**照 M4 P14 的四步（结构 / 视觉 / 交互 / 改成自己的）+ M6 #36/#69 的验收口径**，
选一个**真实的参考 URL**（一个广为人知的**作品集布局范式**），**先出《参考拆解表》三段拆解，再用自己内容重建单页 HTML**，
并在产物里**明写"借了什么方法 / 换了什么内容 / 哪些是占位"**——让看的人明白：
**参考要拆，不能照抄；拆完要换，才算自己的。**
