## 1. 痛点原句（引用手册原文）

**出处 M4 · P10（五步工作流，本案例的方法论母本）**
> 「把需求拆成五步，Codex 更容易做准：01 定目标（谁看、看完后要做什么动作）02 给内容（标题、文案、图片、Logo、模块顺序）03 给参考（说清喜欢的是布局、颜色、字体还是动效）04 生成第一版（先要能打开、能看、结构完整的版本）05 逐项修改（**一次只改一类问题**：内容、布局、交互、移动端）」

**出处 M4 · 开场页（这份 deck 的自我定位）**
> 「少一点名词堆叠，多一点能直接用的判断：网页是什么、JS/C/S/瀑布流是什么，以及怎么用 Codex 做出第一版页面。」

**出处 M4 · P15（交付自检清单，本案例的验收点）**
> 「交付前只看五件事：01 内容真实（没有占位文案、假链接、空图片）02 手机可读 03 交互完整 04 风格统一 05 授权清楚 06 能打开」

**出处 M5 · 结束语 P03（作品与简历的关系）**
> 「作品比简历更快说话。先做出一个能被别人打开的东西。」

## 2. 痛点主体：谁

**不会写代码、也说不清自己要什么，但想做出第一版网页的人**——课上是零基础学员/个体创作者，
（对应案例清单 编程-01 的补全）"想做个网页但不会写代码，也说不清要什么"。

## 3. 旧做法的代价（绑定时长 / 动作量）

- **丢给 AI 一句话** → 得到一版"AI 味"模板页：字体、配色、卡片全是默认感，**拿不出手、不好意思发出去**。
- **自己说不清** → 于是跑去背 HTML/CSS/JS 名词、纠结"用 React 还是 Next.js"，**几小时过去，一个能打开的页面都没有**。
- **找替代路径** → 找外包做一版报价几千、等两周；用建站平台模板又**绑死域名、撞车**。
- **收尾更坑** → AI 说"做完了"，发出去才发现**手机上一个按钮点不到、图片是空的、文案还是 Lorem ipsum**——返工成本全在后头（M4 P15 + M6 格式要求 5）。

## 4. 想要的目标：做到什么程度算"解决好"

一版**能被别人打开、能看、结构完整**的网页：**首屏 + 3-5 个模块 + 响应式（手机可读）**，
并且交付前逐条过 M4 P15 的六条自检。**能本地打开**（单文件 HTML）。

## 5. 【补全】为什么值得解决

手册没把"为什么值得"讲透，补一句并标注【补全】：

【补全】"没有可打开的作品"是接单/求职的**死结**（M5 P03："作品比简历更快说话"）。而"做出第一版"的真正门槛**不在代码**，
在**能不能把'目标 / 内容 / 参考'讲清楚**——把模糊需求翻译成 AI 能执行的四项信息。这一步恰恰是 Agent 能补上、
而用户靠自己最容易卡住的部分。所以这个案例的价值 = **把"工具理性"打回"目标导向"**。

## 6. 价值归类

- ✅ **目标导向**：用户真正要的是"**一个能被别人打开、能看、结构完整的东西**"（结果），不是"学会 HTML/CSS/JS"（手段）。
- ⚠️ **需避免的工具理性陷阱**：去背 HTML/CSS/JS 名词、纠结用 React 还是 Next.js、研究"哪个模型最强"，
  而不是先把"**谁看、看完要做什么动作、手上有什么内容、喜欢什么参考**"讲清楚。

## 7. 本案例复刻意愿（一句话）

**照 M4 P10 的五步法，用一个真实题材（"Codex 五步法"方法本身）从 0 做出第一版网页**，
并在过程中把"定目标 / 给内容 / 给参考 / 生成第一版 / 逐项修改"五步各自留痕——让看的人明白：
**先想清楚，再让 AI 动手**。产物须过 M4 P15 六条自检。
