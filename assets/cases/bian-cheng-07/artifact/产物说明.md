## 怎么用

1. **双击打开**（Chrome / Edge 均可），无需联网、无需安装、无需任何目录。
2. **筛** —— 吸顶那一排按钮：`全部 30` / `网页/UI 设计 10` / `PPT/HTML Slides 5` / `海报/图片生成 5` / `品牌/设计系统 4` / `简历/作品集 5` / `真实人像/模特 1`。
   按钮上的数字是**真实条数**，点之前就知道会剩几条；点完计数行同步变成"当前显示 N / 30 条"。
3. **看** —— 每张卡片左侧深色竖条是**名次**（前 3 名换绿色，这是"榜单"这件事本身的信息）；卡内依次是预览图、分类、仓库名、星标、**适合做什么 / 它做什么 / 审美要点**、标签、来源链接与本地 skill 路径。
4. **复制** —— 点「复制链接」把该条来源仓库地址带走。降级三路：`Clipboard API` → 临时 `textarea` + `execCommand` → 都不行就**自动选中卡片里的链接文本**并提示手动复制。
5. **手机** —— 390px 下卡片单列、正文 13.5px、复制按钮独占一整行（30 个按钮宽度完全一致，390px 下实测均为 302px）；**不横向滚动**。

## 边界与已知限制

- 为了让"单文件"成立，预览图做了有损压缩（760px 宽 / JPEG q=84）。卡片显示尺寸下无差别；**若图片数量到几百张，正确做法是拆成"HTML + 图片目录"并诚实告知接收方，而不是硬内联**（这条边界写在 `讲课大纲.md` 第 3 段）。
- 手机可读性是用 **headless Chrome 的设备模拟**（390×844 / 320×720）量出来的，**未在真实手机上打开验证过**。
- **"30/30 图片加载成功"这句话有个前提**：30 张图都带 `loading="lazy"`，**不滚动的话只看得到 4 张已加载**（审查 Agent 第一轮就因此误判"26 张空白"，滚动后才发现全在）。核验脚本报 30/30 是对的，因为它对每张图调了 `.decode()` 主动触发加载。inline `data:` URI 下 lazy 不产生网络请求，所以是安全的——但这个前提此前没写明。
- `file://` 下的复制依赖浏览器把 `file://` 判为安全上下文（本次实测 `isSecureContext === true`）；若被拒会走 `execCommand` 兜底，再不行自动选中链接文本。
- 榜单内容（30 条 skill 的元数据与预览图）来自案例自带的数据包；页脚标注了数据来源与抓取时间。**不含**原成品的 logo 与任何受版权素材。
