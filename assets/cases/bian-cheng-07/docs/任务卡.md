## 要解决什么（承接痛点卡）

把"**30 条素材只能在自己电脑上打开、改一条要动 HTML、发出去要连 assets 目录一起打包**"
变成"**一个 HTML 文件，双击能开、发出去就能用，筛选和复制真的能用**"。

具体三件事：
1. **数据驱动**——30 张卡片由 `skills.json` 生成，不手写。
2. **真单文件**——30 张预览图压缩后内联成 data URI，HTML 拷给别人就能开。
3. **功能真的能用**——6 个分类筛选、30 个复制按钮、手机 390px 可读不横滚。

## 验收点（供自检与审查）

对照"现成成品"逐条验收——这是元复刻案例，成品在手上，可以 1:1 对：

- [ ] **筛选生效**：6 个分类 + 全部，点下去可见卡片数与数据源各分类条数一致，且只出现该分类。
- [ ] **复制可用**：每条"复制链接"按钮点下去，复制到的内容 == 该卡片的来源链接。
- [ ] **图片加载**：30 张预览图全部渲染出来（`naturalWidth > 0`），不是空图。
- [ ] **手机可读**：390px 宽下能读、不横向滚动、按钮点得到；320px 也兜得住。
- [ ] **真单文件**：0 个外部资源引用（不含 `link/script/img` 外链），拷走一个文件就能开。
- [ ] **内容真实**：无占位文案、无假链接（链接全部来自 `skills.json` 的 `copy_url`）。
- [ ] **不搬素材**：不含原成品的 logo 图片与受版权素材；只借结构与功能方法。
- [ ] **能打开**：文件双击可在浏览器打开（本轮用 headless Chrome 实测）。

## 红线

- 不许只描述不产出：`最终产物/` 必须有真能打开的 HTML。
- 必须做**视觉/功能核验**：headless Chrome 打开、截图、实测筛选/复制/图片/手机宽度，不能只读代码。
- 手机 390px 必须不横向滚动——且**不能靠 `overflow-x:hidden` 把溢出藏起来**（诊断脚本已专门摘掉再看一遍）。
- 截图存证，过程记录逐步写。
- 借方法不抄袭：不拷贝原成品代码与图片素材。
