## 五、已知限制（如实登记，非打回项）

1. **未做真机测试**：手机可读性是通过 CDP `Emulation.setDeviceMetricsOverride`（390×844 / 320×720, `mobile:true`）量出来的，**没有在真实手机上打开过**。
2. **1.34 MB 的取舍**：为了"单文件"把图内联，文件因此偏大。若图片数量到几百张，正确做法是拆成"HTML + 图片目录"并诚实告知（已在 `讲课大纲.md` 第 3 段写明这条边界）。
3. **预览图是有损压缩**：760px / JPEG q=84。在 4K 屏上把卡片放大看会比原 PNG 略软；卡片显示尺寸下无差别（质检截图已确认）。
4. **`file://` 下的复制依赖 `isSecureContext`**：本次实测 `file://` 下 `isSecureContext === true` 且 Clipboard API 可用；若某些浏览器把 `file://` 判为非安全上下文，会走 `execCommand` 兜底，再不行会选中链接文本提示手动复制（三路降级已实测到第二路）。

- 自写 CDP 脚本拉起 headless Chrome（`--remote-debugging-port=0` + 独立 profile），以 `file:///` 打开产物；

- 内容核对**不依赖页面自身 DOM**：把页面里抽出的 30 张卡片的 `h2 / data-category / tags / 文案 / copy_url / local_path / star_label` 与 `输入素材/skills.json` **逐字段比对**；
- 图片与 slug 的对应关系用 canvas 32×32 灰度感知签名做 30×30 最近邻匹配（**生产者未做此项**）；
- 截图用自写 PNG 解码器按原生像素扫描（**不看缩略图下结论**）。

### 关于意见 3：实测比审查报告更严重

审查报告写的是"302px vs ~73px"。生产方用 `measure_copy_width.mjs` 逐视口实测（30 个按钮取宽度去重）：

| 视口 | 修订前按钮宽度种类 | 修订后 |
|---|---|---|
| 390px | **3 种：73 / 80 / 302**（30 个里 27 个只有 ~73px）| **1 种：302** |
| 760px | 5 种：378 / 389 / 428 / 435 / 442 | **1 种：664** |
| 761px 及以上 | 1 种：70（桌面设计，正常）| 1 种：70 |

**根因**：`.repo` 是 `flex-wrap` 容器（内含 `Stars 徽标 / 查看原链接 / 复制链接`），`.copy{flex:1 1 auto}` 的宽度 = **该行前面剩多少空间**，而"查看 GitHub 原链接"的文字长度每条不同 → 按钮宽度跟着变。

**这不只是"观感不齐"**：380px 手机上 27 个按钮只有 ~73px 宽，是偏小的点按目标；而且**生产方 `产物说明.md` 里"390px 下……复制按钮撑满可点"这句话，对大多数卡片本来就不成立**——是审查 Agent 把这句话戳破的。

**修法**：≤760px 下改成 `.copy{flex:1 1 100%}`，按钮独占一行、宽度恒定。
