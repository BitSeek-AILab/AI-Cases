## 一、痛点原句（引用材料原文）

**位置1 · 成品页面的自述（`index.html` 首屏 lead 段，逐字）：**

> 「这份榜单按设计用途重新整理：你可以快速看出它是用来做网页 UI、生图海报、HTML PPT、品牌设计系统，还是简历作品集。」

**位置2 · 案例清单给出的痛点定位（编程-07 条目）：**

> `原文`（其页面自述）「这份榜单按设计用途重新整理：你可以快速看出它是用来做网页 UI、生图海报、HTML PPT、品牌设计系统，还是简历作品集。」
> **补全**：手上有 30 条素材要做成**可浏览、可筛选、可复制的展示站**，**不会写前端，用建站工具又绑死平台**。真正想要的是"**一个单文件、能发出去的目录站**"。

**位置3 · 领域总纲（案例清单·领域三 开篇，M5 结束语）：**

> 「不要在旧赛道卷速度…把"效率"误当成"机会"」
> 「先看市场，再练能力」「作品比简历更快说话。**先做出一个能被别人打开的东西。**」

## 二、痛点主体

- **谁**：手里攒了一批 AI skill / 工具 / 素材，想整理成"能发出去的一份东西"的人——本案例具体化为**帮白无常整理这份设计美学榜单的人**（做内容、做社群、做课程资料的人，不写前端）。
- **场景**：手上已经有 **30 条结构化数据**（`skills.json`，每条含名次、名称、分类、仓库、星标、适合做什么、审美要点、本地路径）+ **30 张预览图**。要把它们变成"别人能打开、能翻、能筛、能复制走"的一页。
- **交付对象**：发到群里 / 发给同事 / 当课程配套资料的人。**"能发出去"是硬指标**。

## 三、旧做法的代价（绑定时长 / 动作量）

对着成品实测出来的三条代价：

| 旧做法 | 具体代价（可核算） |
|---|---|
| 手工写 HTML 卡片 | 原成品 `index.html` 里 **30 张卡片是逐字手写死的**（脚本实测：`<article class="skill-card">` 出现 **30** 次，无数据渲染）。**改一条要动 HTML，改 30 条要动 30 处。** |
| 图片靠外部文件 | 30 张预览图是 **30 个独立 PNG**（`assets/previews/*.png`，合计 **7.37 MB**），HTML 里 30 个 `<img src>` **全是外链，0 个内联**。发出去必须连 `assets/` 一起打包——**少一个目录，整页图全空**。 |
| 用建站工具 | 拖拽式建站能出筛选和卡片，但**绑死平台**：导出受限、域名绑死、样式改不动，且"发出去"变成"发一个平台链接"，**不是一份可以随手转发的文件**。|

**真正想要的结果**：一个 `.html` 文件，双击能开、发出去就能用——**不用配环境、不用带目录、不用登录平台**。

## 四、想要的目标（做到什么程度算"解决好"）

1. **单文件**：拷走**这一个** HTML 就能发给别人，不依赖 `assets/`、不依赖网络、不依赖平台。
2. **可浏览**：30 条一眼看得清"哪条是干什么用的"，卡片网格 + 预览图 + 名次。
3. **可筛选**：6 个分类能一键收敛（网页 UI / PPT / 生图 / 品牌 / 简历 / 人像）。
4. **可复制**：每条能一键把来源链接带走，不用手动选中长 URL。
5. **移动端可用**：手机上（390px）能读、不横向滚动、按钮点得到——因为"发出去"的主要场景就是**别人用手机点开看**。

## 五、【补全】

【补全】案例清单已经点出"要单文件、能发出去"，但**没讲透"为什么值得解决"**，这里补三句：

- **这类"目录站"的价值不在页面本身，在于它能不能被传下去。** 30 条素材如果只能在自己电脑上打开，它就只是一份私人笔记；一旦变成一个能随手转发的单文件，别人才可能真的用它——这正好落回 M5 那句「先做出一个能被别人打开的东西」。
- **痛点不是"不会写前端"，而是"不敢改"。** 手写死的 30 张卡片有个隐蔽代价：**你不敢动它**。名次变了、图换了、分类要调一个，成本是重新做一遍。所以复刻的真正目标不是"再做一个好看的页面"，而是**把结构从"手写内容"变成"数据驱动"**——数据改一行，页面跟着变。
- **"内联"不是炫技，是分发的必要条件。** 7.37 MB 的图压到 0.95 MB 再内联，换来的是一句"发这一个文件就行"。这一步是痛点能不能被真正解决的**分水岭**：不做内联，"发出去"就永远要附带一句"记得把 assets 文件夹也发上"。

—— 这一点也解释了为什么验收点里"图片加载"要和"单文件"绑在一起看：**图在单文件里能加载出来，才算真的解决。**

## 六、价值归类

✅ **目标导向**：用户要的是"**一份能发出去、随手能用的目录站**"（结果：别人打开就能用）→ 所以把数据、图、交互全部收进一个文件。
❌ 非"工具理性"：不是"我有个 index.html 所以找个办法优化它"。工具理性的陷阱在这类任务里非常具体——**去研究前端框架、纠结用 Grid 还是 Masonry、比较哪个建站平台的模板好看**，而真正该先回答的是"发给谁、他打开后要能干什么"。
