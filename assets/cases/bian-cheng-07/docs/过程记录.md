## 2. 照做（三阶段）

### 阶段1 · 素材与数据核对 → `audit_data.py`

清点出三个关键数字：

- **30** 条数据（rank 1..30 连续）、**6** 个分类；
- **30** 张预览图与 slug 一一对应，合计 **7.37 MB**；
- 原成品：`<article class="skill-card">` **30 次**（卡片手写死）、`<img src>` **内联 0 / 外链 30**。

**这三个数字直接决定了后面怎么做。**（细节见 `阶段1_素材与数据核对/阶段记录.md`）

### 阶段2 · 单文件实现 → `prep_previews.py` + `build_site.py`

1. 图片压缩内联：**7.37 MB → 0.95 MB**（760px 宽 + JPEG q=84）→ 压到 12.9% 才有资格做"单文件"。
2. 调 `frontend-design` 定美学方向（避开三条 AI 默认长相 → 标本册/索引卡路线 → 名次脊柱作签名元素）。
3. 生成 HTML：**1.34 MB**，30 条卡片全部由数据生成，预览图全部内联，0 个外部资源。

**踩坑 2 个**（详见阶段记录）：Pillow 在用户级 site-packages 被 `-I` 丢掉；分类顺序常量名字写错导致静默错序。

### 阶段3 · 功能与视觉核验 → `verify_site.mjs` + `diagnose_overflow.mjs`

用 headless Chrome + CDP（零第三方依赖）**实测**，不是"看着像"：

| 验收点 | 取证方式 | 结果 |
|---|---|---|
| 筛选生效 | 逐个点 7 个按钮，数真实可见卡片 | 30/10/5/5/4/5/1 全部吻合 ✅ |
| 复制可用 | 拦截 `navigator.clipboard.writeText` 做探针，点 30 个按钮比对内容 | 30/30 内容 == `data-copy` == 显示链接 ✅ |
| 图片加载 | 30 张 `await decode()` + `naturalWidth > 0` + src 全是 `data:image/` | 30/30 ✅ |
| 手机可读 | 390 / 320 两个宽度量 `innerWidth` 与 `scrollWidth`（两段判据） | 无横滚、`innerWidth == 390` ✅ |
| 单文件 | 数 `link/script/img` 外部资源引用 | 0 个（原成品 30 个）✅ |

**这一步抓出并修掉了一个真 bug**（本案例最有价值的发现）：

- 报告一度显示"390 下无横向滚动"，但 `window.innerWidth` 是 **422** 而不是 390。
- 两层掩盖：① `body{overflow-x:hidden}` 把真实溢出**裁掉**了；② Chrome 移动端遇溢出会 **shrink-to-fit**，不产生横滚条，而是把视口撑大。
- `diagnose_overflow.mjs` 做两段对照（`mobile:true` 看真机行为 + `mobile:false` 且用 `!important` **摘掉 overflow** 看真实溢出）→ 确认 `doc.scrollWidth = 422 > 390`。
- 真凶：卡片底部的仓库 URL 是**超长不可断词**，`.src .url` 没设断词规则，把 `body.scrollWidth` 顶宽 32px。
- 修复（`overflow-wrap:anywhere` + `word-break:break-word` + `.filters{min-width:0}`）后 **422 → 390**。
- **同时把判据本身修了**：`verify_site.mjs` 增加硬断言 `innerWidth === 390`，并把"摘掉 overflow 后的严格判据"列为独立通过项——否则这个 bug 会被"没有横滚条"永久掩盖。

## 坑（集中登记）

1. **Pillow 在用户级 site-packages，`py -I` 会丢掉它** → 脚本内 `sys.path.append(site.getusersitepackages())`（`-I` 隐含 `-E`，`PYTHONPATH` 无效）。
2. **构建脚本的分类顺序常量写错一个分类名会静默错序**（有兜底所以不丢数据）→ 构建输出必须打印分类分布。
3. **lazy 图核验不能用定时等待** —— 3 张图被误判为坏图，改"分步滚动 + eager + `decode()`"后 30/30。
4. **`overflow-x:hidden` 会把横向溢出藏起来**，"没有横滚条"是假通过 → 必须摘掉再看一遍。
5. **Chrome 移动端 shrink-to-fit 会骗过 `scrollWidth` 判据** → 必须额外断言 `innerWidth === 目标宽度`。
6. **超长不可断词（URL）是移动端溢出的头号嫌疑** → `.src .url` 这次就是它。
7. Git Bash 控制台是 GBK，python 打印中文乱码 → 一律"脚本写 UTF-8 文件 + 用 Read 工具读"，或 `iconv -f gbk -t utf-8`（沿用 `运行日志.md` 坑4 的结论）。
