## 全流程踩到的坑（供后续案例复用）

### 坑 1 · python-docx 新建 run 直接取 `rPr.rFonts` 可能是 None
- `r = p.add_run(...)` 后直接 `r._element.rPr.rFonts.set(...)` 报 **`AttributeError: 'NoneType' object has no attribute 'set'`**（新建 run 尚无 rFonts 子节点）。
- **解法：先 `run.font.name = "微软雅黑"`（创建 rFonts），再 `rPr.get_or_add_rFonts().set(qn("w:eastAsia"), ...)`。**

### 坑 2 · Python 字符串里的中文引号要小心（与办公-12 同源坑）
- 摘要/结论文案里写了 ASCII `"…"` → 提前结束字符串，报 `SyntaxError: invalid character '、'`。
- **结论：中文文案里一律用全角「」/“”，别用 ASCII 引号。**

### 坑 3 · 章节抽取要按"节标题状态机"，并用样式过滤
- 若只按"下一个节标题"当边界、且不过滤样式，会把标题/信息行误当要点。
- **解法：遇"一、二、三、"节标题才切换状态，且只收 `List Bullet` 样式的段落。**

### 坑 4 · 禁用通道（沿用办公-01/02/03/12）
- `mcp__agent-vision__analyze_image` **返回 401** → 文档类核对走"python-docx 回读 + 直接 Read"，无需视觉通道；
- 一律用 `py -3`（`E:\miniconda3`）才有 python-docx；
- **不用 Word COM 出 PDF**（本案例只出 docx/md，不依赖 Office 组件）。

## 规模可扩展性说明

手册痛点是"3–5 份材料提炼共同主题"。本案例脚本**对输入目录里任意份数 docx 循环**——`read_reports.py` 读全部、`synthesize.py` 的口径不变。**材料从 3 份变成 5 份、10 份，只增加读取条数，"横向对齐 → 共同主题 → 综合报告"的方法不变**。这正是"每个季度、每个月都要来一次、材料越多越难对齐"痛点的真正解药。
