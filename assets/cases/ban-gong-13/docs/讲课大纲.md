# 讲课大纲 · 办公-13 多文档综合：提取共同主题生成综合报告

> 手册本案例是一条指令模板，没有展开讲法。本大纲按《子Agent执行规范》要求，把"案例如何展开"补出来（标注【补全】）。

---

## 一句话定位

**学员带走的能力：** 把"3 份各讲各的部门报告"变成"一份提炼出共同主题、标注了出处的综合报告"。
**不讲的东西：** 不讲公文写作格式、不讲排版。学员不需要会，也不该会。

---

## 开场（3 分钟）：先制造痛，再给答案

【补全】开场三选一，本案例用"现场还原"。

**做法：** 现场打开 `输入素材/` 里 3 份报告，**并排铺开**——
- 市场部讲 CAC 降了 29%、AI 做创意；客服部讲响应 28 秒、AI 解决率 46%；研发部讲交付率 94%、大模型接口——
- 数字都不一样、话术都不一样。现在要写一份"跨部门综合报告"向上汇报。
- **最要命的是**：一顺手，就会写成"市场部讲了A、客服部讲了B、研发部讲了C"——**三段拼接，恰恰没有"综合"**。

**关键提问（停顿，等学员答）：**
> "'综合报告'和'三份报告拼在一起'，区别在哪？"

引导学员自己说出：**综合报告要提出"跨部门共同出现的主题"**，而不是逐份复述。

**收口：** "3 份对读、横向对齐、写成报告，人工约 **2 小时**；而且材料越多，横向对齐越难（乘法级）。更麻烦的是——**最容易写成'每篇讲了什么'，看不出'共同主题'**。这就是今天要解决的问题。"

---

## 主体（20 分钟）：走一遍真实链路

### 第 1 步 · 一句提示词启动（1 分钟）

念手册原句：

> **多文档处理：同时处理[文档1]、[文档2]、[文档3]，提取共同主题，生成综合报告**

强调：**不需要**先说"你要先读三份、再划重点、再横向对齐、再找差异、再配出处、再成文"。一句话，Agent 自己拆步骤，最后交出**一份能交上去的综合报告**。

### 第 2 步 · 逐份读（4 分钟）：讲"先看清每份，才能横向比"

展示 Agent 先**逐份读** 3 份 docx，把每份的"成果 / 问题 / 计划"抽出来，落成结构（每份的关键数字都留住）。

**关键提问：**
> "要提炼共同主题，第一件事是'直接写'还是'先读透每一份'？"

答：**先读透每份**。共同主题是"横向比"出来的，比之前得先知道"每一份到底有什么"。**顺序错了，就会漏掉某一份里的关键信号。**

### 第 3 步 · 提炼共同主题（6 分钟）：讲本案例最高价值的一步

展示 Agent **横向对齐**三份，提出**共同主题**，每条**至少挂 2 份来源**：

| 共同主题 | 市场部 | 客服部 | 研发部 |
|---|---|---|---|
| **AI 落地提效** | AI 做创意，产出 +220% | AI 智能客服，解决率 46% | 大模型接口支撑 5 场景，评审效率 +30% |
| **客户/用户体验** | 私域转化链路 / 体验一致性 | CSAT 93% / NPS 42 | P95 延迟 420→210ms |
| **降本增效 / 人效** | CAC -29% | 人效 +35% | 交付率 94% / 故障 5→1 |
| **数据驱动** | 投放归因看板 | 问题分类看板 | 研发效能看板 |

**关键提问（本案例最高价值的一问）：**
> "为什么每条'共同主题'都要挂上来源文档？"

答：因为**综合报告最怕"看起来有观点、其实没依据"**。挂上来源，读者（管理层）能回原报告核——**这是让"AI 归纳"变得可信的关键一步**：不是让你信它，是让你能**验证**它。

> **收口：** "'每篇讲了什么'和'共同主题是什么'长得很像。**AI 最容易被带偏、也最需要人守的一关，就是守住'综合'——每条主题至少横跨 2 份材料。**"

### 第 4 步 · 找差异点（4 分钟）：讲"共同之外，还要看出不同"

展示差异点：三家**侧重不同**——市场部=增长与投放；客服部=服务与满意度；研发部=交付与稳定。**AI 的定位也不同**：市场部当"生产工具"、客服部当"服务前台"、研发部当"能力底座（对外开放）"。

**关键提问：**
> "共同主题都提完了，为什么还要专门写一节'差异点'？"

答：因为**共同主题告诉你'公司层面在做什么'，差异点告诉你'每个部门各自的短板和重点在哪'**。只有共同、没有差异，报告就没法指向"下一步各部门该怎么协同"。

### 第 5 步 · 配出处与成文（5 分钟）：讲"能交出去才算完成"

展示产出的综合报告（docx 主件 + md）：
- 版式：报告信息 / **一、共同主题（★，每条挂来源）** / **二、差异点** / **三、结论与建议** / 附来源索引；
- **A4 竖版、可直接打印/上传**。

**关键提问：**
> "综合报告的结论该怎么推？"

答：从**共同主题**里推——三部门都在做 AI、都在抓体验、都要增效、都在数据驱动，那么**下季度的跨部门协同重点**自然是"AI 能力统一治理 + 全链路体验 + 数据打通"。**结论不是拍脑袋，是共同主题的必然推论。**

## 收尾（7 分钟）：从"这一次"到"每一次"

### 对比表（板书/投屏）

| | 手工 | 本次链路 |
|---|---|---|
| 逐份读 | 3 份各 10 分钟 | 3 份一次读入 |
| 划重点 | 手工标记 | 按"成果/问题/计划"结构抽出 |
| **找共同主题** | 横向对齐，最费脑、易写成复述 | 横跨 ≥2 份才算主题 |
| 找差异点 | 容易写成"都重要" | 显式对比三家侧重 |
| 配出处 | 回翻手工核，易错 | 每条挂来源文档 |
| 成文 | 再写一轮 | 一次成文 |
| **耗时** | **约 2 小时** | **分钟级** |
| **下季度** | **再来一遍** | **换几份材料，重跑一次** |

### 收束提问（回扣痛点卡）

> "今天真正省下来的，是那 2 小时吗？"

引导到正确答案：**省下来的是"横向对齐"这件最费脑的事，以及"只复述、无综合"的风险。**

### 留给学员的一句话

> "你不需要会写综述。你需要会**看出'三份材料在说同一件事'**，以及**要求每条观点都能回到出处**。"

---

## 板书/PPT 要点（备查）

1. 一条顺序：**先读透每一份，再横向比**
2. 一条红线：**"每篇讲了什么" ≠ "共同主题"**（主题至少横跨 2 份）
3. 一个动作：**每条论点挂来源** —— 让归纳**可回溯、可验证**
4. 一节不能少：**差异点**（共同之外，看出不同）
5. 一条原则：**结论从共同主题推**，能交出去才算"写完了"
