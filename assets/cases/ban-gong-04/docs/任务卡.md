| # | 交付物 | 路径 | 形态 | 说明 |
|---|---|---|---|---|
| 1 | 批量转换后的 PDF ×6 | `最终产物/周报PDF/周报_2026XXXX.pdf` | PDF | 按"文档内报告日期"命名：0626/0703/0710/0717/0724/0731 |
| 2 | 重命名对照表 | `最终产物/重命名对照表.xlsx` | Excel | 原文件名 → 文档内报告日期 → 新文件名 → 输出路径 → 页数/大小/状态 |

**交付物对应手册原句：** "所有Word转PDF" → ①；"按日期重命名" → ①的命名 + ②的对照。

---

## 命名规则（本案例的核心）

```
新文件名 = 周报_{文档内"报告日期" YYYYMMDD}.pdf
```

- **日期取自文档内容**，不取文件名——因为文件名里的日期可能是保存日期，不一定是报告日期（见痛点卡第 2 条陷阱）。
- 示例：`周报_0724.docx`（文件名误导）→ 内容报告日期 2026-07-31 → **`周报_20260731.pdf`**。

---

## 输入素材

`输入素材/`（6 份 .docx，"市场部周报"，作者张伟）：

| 原文件名 | 文档内报告日期 | 说明 |
|---|---|---|
| `市场部周报.docx` | 2026-06-26 | 名字完全不带日期 |
| `周报-终稿.docx` | 2026-07-03 | 名字不带日期 |
| `周报 张伟 2026.07.10.docx` | 2026-07-10 | 名字含正确日期 |
| `周报_0717(1).docx` | 2026-07-17 | 名字含正确日期 |
| `周报_0724.docx` | **2026-07-31** | ⚠ **陷阱**：文件名日期 ≠ 报告日期 |
| `Word版周报.docx` | 2026-07-24 | 名字不带日期 |

> 手册场景为"D盘周报文件夹里所有 Word"。真实情况是文件名不规范、日期得开文件才知道。本素材刻意做成"文件名与内容日期不一致"，取日期必须读内容——这正是手工最容易改错的地方。

## 验收点（自检表逐条对应）

1. 3 类交付物真实落盘、能打开（6 个 PDF 可开且逐页可读；2 个 xlsx 可开）——**不许只描述不产出**
2. 6 份 Word **全部**转成 PDF，**不多不少**（输出目录文件集 = 输入文件集映射）
3. 命名**取自文档内容日期**：`周报_0724.docx` 必须得到 `周报_20260731.pdf`（**不是** `周报_20260724.pdf`）
4. 6 个新文件名**日期互不重复**、覆盖 0626/0703/0710/0717/0724/0731
5. PDF 内容日期与文件名日期**逐份一致**（回读 PDF 文本核对）
6. 对照表与输出目录**逐项一致**（原名/新名/页数/大小）
7. 按手册步骤顺序执行，未跳步、未擅自增加手册没要求的产物形态（不做 PPT / 不做交互页）
8. 【替代】标注齐全（无 LibreOffice → Word COM 导 PDF；WorkBuddy 插件 → docx/pdf skill + 文件系统脚本）

## 明确的边界（不做的事）

- 不做"定时任务"（那是**案例 6 / 办公-05** 的主题，本案例只做这一次批量转换）
- 不搬运真实 D 盘文件夹（本机无该路径；用**自造等价素材**落 `输入素材/`，路径可由脚本参数替换）
- 不引入手册未提及的图片 OCR / 内容改写等能力（本案例只做"转格式 + 按规则改名"）
