# 讲课大纲 · 办公-04 文档批量转格式 + 按规则重命名

> 手册本案例只有一句话提示词，没有展开讲法。本大纲按《子Agent执行规范》要求，把"案例如何展开"补出来（标注【补全】）。

---

## 一句话定位

**学员带走的能力：** 把一个"命名乱七八糟的 Word 文件夹"变成"一套按日期规范命名、可归档的 PDF"。
**不讲的东西：** 不讲 PowerShell 批量重命名语法、不讲 Word"另存为 PDF"的菜单在哪。学员不需要会，也不该会。

---

## 开场（3 分钟）：先制造痛，再给答案

【补全】开场三选一，本案例用"现场还原"。

**做法：** 现场打开 `输入素材/` 文件夹，让学员看见里面 6 个名字各不相同的 Word：
`市场部周报.docx`、`周报-终稿.docx`、`周报 张伟 2026.07.10.docx`、`周报_0717(1).docx`、`周报_0724.docx`、`Word版周报.docx`。

**关键提问（停顿，等学员答）：**
> "月底要把这一文件夹周报转成 PDF 归档、还得按日期命名。你第一步要干什么？"

引导学员自己说出：**得逐个点开看里面的报告日期**——因为光看文件名，有一半根本不知道是哪一周的。

**收口：** "20 份就是开 20 次、另存 20 次、改名 20 次，20 到 30 分钟，每月底重来一次。而且更麻烦的是——**文件名里的日期不一定对**。这就是今天要解决的问题。"

---

## 主体（20 分钟）：走一遍真实链路

### 第 1 步 · 一句提示词启动（1 分钟）

念手册原句：

> **把D盘"周报"文件夹里所有Word转PDF，并按日期重命名**

强调：**不需要**先说"先遍历文件、再读内容、再调 Word、再改名"。一句话，Agent 自己拆步骤，最后交出**命好名的 PDF**。

### 第 2 步 · 清点 + 读内容取日期（6 分钟）：讲"日期从哪来"

展示 Agent 不是靠文件名猜，而是**逐份打开读"报告日期"**：

| 原文件名 | 文件名里的日期 | 文档内报告日期 |
|---|---|---|
| `市场部周报.docx` | 无 | 2026-06-26 |
| `周报-终稿.docx` | 无 | 2026-07-03 |
| `周报 张伟 2026.07.10.docx` | 07-10 | 07-10 ✅ |
| `周报_0717(1).docx` | 07-17 | 07-17 ✅ |
| **`周报_0724.docx`** | **07-24** | **07-31** ⚠ |
| `Word版周报.docx` | 无 | 2026-07-24 |

**关键提问（本案例最高价值的一问）：**
> "`周报_0724.docx` 这份，新名字该叫什么？"

学员大概率会答 `周报_20260724.pdf`（**看名字改**）。
**答案是 `周报_20260731.pdf`**——因为打开看内容，里面写的是"报告日期：2026年7月31日"。它是一份**另存后没改文件名**的文件。

> **收口：** "靠文件名改，你会把 7/31 的周报归档成 7/24。**转出来的 PDF 完全正常，错在周次，而且没人会发现**——等要查的时候才发现归档是乱的。"

**这 一步的板书金句：** "**按内容改名，不按文件名改名。**"

### 第 3 步 · 批量转 PDF（5 分钟）：讲"怎么不漏"

Agent 的取数逻辑是"**扫文件夹 → 对每一份都做 → 输出到指定目录**"，跟文件数无关：6 份这么做，20 份、200 份也这么做。

**关键提问：**
> "如果文件夹里有 20 份、40 份呢？中途打断了怎么办？"

答：**规则固定，重跑一遍即可**；输出的对照表会列出每一份的处理结果，漏了哪份一眼看得出来。**人做这件事最怕的不是慢，是打断之后"记不清做到哪份了"。**

### 第 4 步 · 出对照表（4 分钟）：讲"改名要留痕"

展示 `重命名对照表.xlsx`：**原文件名 → 报告日期 → 新文件名 → 输出路径**。

**关键提问：**
> "改完名，原来的名字还需要留着吗？"

答：**要**。改名是"不可逆"的动作——**留一张对照表，等于给这次批量操作留了后悔药**。哪天发现改错了，照着表能倒查回去。这也解释了为什么"日期从内容取"必须写进表里：**让改名的依据是可复核的**。

### 第 5 步 · 收尾验收（4 分钟）：讲"怎么确认没改错"

现场演示核对：**回读每个 PDF 的文本，确认文件名里的日期 = PDF 里的报告日期**。

**关键提问：**
> "6 份都对，就说明没错了？"

答：**还要看数量**——输入 6 份，输出就必须是 6 份；对着对照表数一遍，多一份少一份都要说清楚。

## 收尾（7 分钟）：从"做完这一次"到"以后每个月"

### 对比表（板书/投屏）

| | 手工 | 本次链路 |
|---|---|---|
| 找文件 | 逐个看名字猜周次 | 扫描文件夹统一处理 |
| 取日期 | 逐份点开看（20 次） | 脚本读文档内容取日期 |
| 转 PDF | 逐份另存 | 一次批量转换 |
| 改名 | 逐个输入，易改错周次 | 固定规则，按内容日期命名 |
| 留痕 | 没有 | 自动出对照表 |
| **耗时** | **20–30 分钟** | **分钟级** |
| **下个月** | **再来一遍** | **换一批 Word，重跑一次** |

### 收束提问（回扣痛点卡）

> "今天真正省下来的，是那 20–30 分钟吗？"

引导到正确答案：**省下来的是"改错周次却没人发现"的风险，和"每个月还要再来一遍"。**

### 留给学员的一句话

> "你不需要会批量重命名。你需要会**说清楚规则**，以及**看得懂对照表对不对**。"

---

## 板书/PPT 要点（备查）

1. 一个动作：扫文件夹、逐份处理、输出到指定目录（数量多少都一样）
2. 一个规则：`周报_{文档内报告日期}.pdf`
3. 一个陷阱：文件名日期 ≠ 内容日期（`周报_0724.docx` → `周报_20260731.pdf`）
4. 一条留痕：改名要出对照表，可倒查
5. 一条红线：输出数量必须 = 输入数量，不多不漏
