# 讲课大纲 · 案例编程-09 交互提示词库

> 手册只给了主题（"能搜能复制的小工具页"），本大纲把它展开成可直接讲的 6 段。

---

## 这节课要学员带走的判断

**"存起来"和"捞得出来"是两回事。**
一份 152 段长文本的 Markdown，你拥有的是"资料"；一个能搜能筛能一键复制的页面，你拥有的才是"工具"。
**判断标准很简单：你写代码的时候，会不会真的去打开它。**

---

## 第 1 段 · 先搞清楚"料在不在"（4 分钟）★本案例特有的坑

**讲什么**：这个案例的料**不能靠扒页面拿**。

- 现场取证：脚本数静态 HTML 里 `<article class="card">` 出现次数 → **只有 1 次**（那是 JS 渲染用的模板外壳）。
- 结论：**页面里 76 条提示词全在 `<script>` 的 JS 数组里，静态剥标签一条都拿不到。**
- 正确做法：`prompts_extracted.json`（本项目在上一轮已踩坑解决，见 `运行日志.md` 坑2）。

**为什么这时候讲**：这是"看起来拿到数据了"和"真的拿到数据了"的分界。**你的脚本"成功运行、返回结果"不等于"结果是对的"。**

**互动提问**：如果你只做了"爬下来一份 HTML"，怎么发现它是空的？（答：数关键节点的出现次数，而不是数文件大小。）

## 第 2 段 · 清点数据，量出可核算的痛点（5 分钟）

**讲什么**：把"不好用"变成数字。

现场读 `阶段1_数据核对与结构设计/产物/数据核对报告.txt`：

| 量出来的事实 | 数字 |
|---|---|
| 条目 | 76 条，中英两份都非空（8 个字段全部 76/76 覆盖）|
| `promptZh` 长度 | min 50 / **中位 84** / max 154 字符 |
| `promptEn` 长度 | min 63 / **中位 826** / max 2051 字符 |
| 英文原文含 `Acceptance`/验收段落 | **29 条** |
| 英文原文含 `[PLACEHOLDER]` 占位符 | **74 条** |
| 分类 | 3 类（纯交互动态 47 / 参考复刻 27 / Skill 模板 2）|
| 标签 | 148 种；最高频 `Codex/Gemini 通用` 45 条 |
| **原成品实际渲染** | **只有 55 条**（`hiddenReferenceTitles` 里 21 个标题命中数据源）|

**这一段最该讲的三个追问**：

1. **中文摘要只有 84 字符、英文原文 826 字符——差 10 倍。** 这说明 `promptZh` 是"用途摘要"，不是"能交出去的指令"。
   → 所以"复制中文"如果只搬那 84 字符，用户拿到手还得自己补"要做到什么程度、哪里要替换"。**复制只完成了一半。**
2. **"74 条带占位符"意味着什么？** → 复制出去的中文必须**显式列出要替换什么**，否则用户不知道哪里改成自己的品牌/产品。
3. **"只渲染 55 条"算不算 bug？** → 技术上不是；**但它是最隐蔽的一种失效**：用户不知道有 21 条不存在。**一个库最不该做的事，就是让用户以为自己看到了全部。**

## 第 3 段 · 把"复制中文"合成出来（6 分钟）★核心方法

**讲什么**：**"复制"这个动作的质量，决定了这个工具值不值得用。**

- 打开 `build_library.py` 里的 `zhFull(p)`，逐段讲它凭什么这么拼：

  | 段 | 内容 | 从哪来 |
  |---|---|---|
  | 标题 | `# 3D 产品卷轴叙事（3D Product Scroll Story）` | `titleZh` + `titleEn` |
  | 用途 | 那段中文摘要 | `promptZh` |
  | 交互要做到 | 3 条通用要求（状态要真的能触发 / 滚动有可见变化 / 选中态明确） | 页面底部 6 条格式要求的第 1、2 条 |
  | 实现要求 | 单 HTML / 键盘可用 / 移动端不重叠不横滚 / 无 WebGL 降级 / 尊重 reduced-motion | 第 3 条 |
  | 占位符 | `[PRODUCT_NAME]、[BRAND]、[FEATURE_1]…` | **构建期从英文原文正则捞出来**（`extract_vars()`）|
  | 验收标准 | 4 条自检项 | 第 4、5 条 |

- **关键点**：这五段不是编的，是**原成品页面自己列的 6 条"格式要求"**。原成品的"复制中文"只做到两段（标题+用途），本案例把它补全到五段。

**为什么这时候讲**：这是本案例真正的"赋能点"——**不是把数据搬进网页，而是让搬出来的东西能直接用。**

## 第 4 段 · 筛选的语义（4 分钟）

**讲什么**：**"分类"和"标签"是两件事，不该塞进同一条 tab。**

- 原成品的判定条件（现场读它的源码）：
  ```js
  const tabMatch = activeTab === "全部" || item.category === activeTab || item.tags.includes(activeTab);
  ```
  → 点"重 WebGL"和点"参考复刻"看起来是同一个动作。**语义不清，而且没法"在某一类里再按标签收窄"。**
- 本案例改成两层：
  - **分类 = 单选**（全部 / 纯交互动态 / 参考复刻 / Skill 模板）
  - **标签 = 多选，取交集**（Codex/Gemini 通用、单 HTML 优先、重 WebGL、高风险/重性能）
  - 两层**可以叠加**。
- 现场演示：点"参考复刻" + 点"重 WebGL" → 6 条。**这就是"在参考类里只要重 WebGL 的那些"。**

**为什么这时候讲**：筛选器的设计是**语义设计**，不是按钮摆法。

## 第 5 段 · 核验：三条"看起来通过"的假象（7 分钟）★红线

**讲什么**：**这一段的每一个坑，本案例都真实踩过。**

现场跑 `verify_library.mjs`，然后重点讲这三个判据陷阱：

### 陷阱 1 · "总数对"不等于"条对"
数出来 76 条就以为齐了？**要逐条比对标题集合。**
本案例的核验脚本就是这么做的：拿数据源的 76 个 `titleZh` 和页面渲染的 76 个 `h2` 做集合比对，报告缺漏 / 多出 / 重复三项都是 0。

### 陷阱 2 · "按钮有反应"不等于"内容对"
复制按钮点了变字，不代表复制对了。
→ **拦截 `navigator.clipboard.writeText` 做探针**，把复制到的字符串抓下来，**逐字**和页面 pre 的全文比对。
本案例因此能给出硬结论：中文复制 **635 / 613 / 574 / 551 字符**，全部**逐字等于**页面那段 pre —— 而且是在**正文被折叠（`scrollHeight 669` 但 `clientHeight` 只有 190）**的状态下。

### 陷阱 3 · "手机不横滚"可能是被藏起来的
- `body{overflow-x:hidden}` 会把真实溢出**裁掉**；
- Chrome 移动端遇溢出会 **shrink-to-fit**，不产生横滚条，而是把视口撑大（目标 390，`innerWidth` 报 422）。
→ 判据必须两条：**① 摘掉 `overflow-x:hidden` 再看 `doc.scrollWidth`；② 断言 `innerWidth === 目标宽度`。**

**本案例的产物也是这么抓出过 bug 的**（见 `阶段记录.md`）：测试报了 `getComputedStyle(...) is not of type 'Element'` → 查出英文栏**从来没被加上 `pane-en` class**，导致中英之间的虚线剖面线**根本没生效**。修完才出来。

**为什么这时候讲**：这一步是"做完了"和"验收通过"的分界（呼应编程-12）。

## 第 6 段 · 收束：把库变成习惯（2 分钟）

**讲什么**：

- 现场演示：输 `shader` → 4 条；点"重 WebGL" + "高风险/重性能" → 6 条；点某条"复制中文" → 粘进对话框就是一整份能交的指令。
- 一句话收束：
  > **一个提示词库的价值，不在于它收了多少条，在于你写代码的时候会不会真的去打开它。**
  > 能搜、能叠筛、一键复制出**能直接用**的那一份——这三件事做到，它才会被打开。

## 板书：这节课的五个数字

| 数字 | 含义 |
|---|---|
| **76 → 55** | 原成品只渲染 55 条（静默藏掉 21 条）|
| **74 / 76** | 带占位符的条数 —— "复制中文"必须显式列出要替换什么 |
| **29 / 76** | 英文含验收段落的条数 —— 中文那份要把它补上 |
| **5 段** | 中文复制文本的结构（用途/交互/实现/占位符/验收）|
| **152** | 单条复制按钮总数（76 × 中英各一）|

## 常见追问

- **"为什么不做个后端？"** → 工具理性的典型。76 条数据 0.24 MB，静态单文件能秒开、能离线、能随手发；上后端换来的是"要部署、要联网、要维护"，**换不到任何用户能感知的好处**。
- **"为什么默认折叠，不怕用户看不到全文吗？"** → 76 条全展开是几千屏，手机上没法用。折叠 + 「展开全文」，但**复制永远给全文**——这个保证是显式核验过的（折叠状态下 `zhGot === zhPre.textContent`）。
- **"参考来源那 9 条外链为什么留着？"** → **引用来源 ≠ 搬运内容**。底部 6 条格式要求是**用自己的话重写**的，外链是让别人能追溯取材方向。
