**这一步抓出并修掉了一个肉眼容易放过的真 bug**（本案例最有价值的发现）：

- 核验脚本抛 `getComputedStyle(...) is not of type 'Element'` → 查出 `document.querySelector('.pane-en')` 是 **null**。
- 根因：`paneHtml()` 生成的是 `class="pane" data-side="en"`，**从来没加 `pane-en` 这个 class**；而 CSS 里的中英虚线剖面线写的是 `.pane-en{...}`。
- **也就是说：签名元素"中英剖面线"从头到尾没生效**。桌面截图里两栏之间是光秃秃的——**只靠肉眼看截图很容易以为"还行"就直接放过**。
- 修复 `class="pane pane-' + side + '"` 后剖面线出现，窄屏横向分隔也生效。
- 顺带两处打磨（也是看图之后才发现的）：手机 `pre` 字号 11.5px → **12.5px**（等宽可读下限）；**手机工具栏取消吸顶**（折行后 ~370px 高，会吃掉 844px 视口的四成多）。

## 坑（集中登记）

1. **"原页面用 JS 渲染"= 剥 HTML 拿不到内容** —— 判据：数关键节点出现次数（这里 `<article class="card">` 只有 1 次），不要只数文件大小（170 KB 看着"有料"）。
2. **分类名常量写错会静默错序**（有兜底所以不报错、不丢数据）→ 构建输出必须打印分类分布。
3. **Python 字符串里混用 ASCII 引号当中文引号** → 统一用 `「」`（本项目多次踩到，登记复现）。
4. **CSS 类名只在 CSS 里写、JS 生成时忘了加** → 结果"设计元素根本没生效"，且**肉眼容易放过**。这类 bug 只能靠"用脚本断言元素存在"抓出来。
5. **手机端工具栏吸顶会吃掉大半屏** —— 移动端 sticky 之前先量它折行后的实际高度。
6. **`overflow-x:hidden` 会把横向溢出藏起来**、**Chrome 移动端 shrink-to-fit 会骗过 `scrollWidth` 判据** → 判据必须"摘掉 overflow 再看" + "断言 `innerWidth === 目标宽度`"（沿用案例07 的结论，本案已内建）。
7. Git Bash 控制台是 GBK，python 打印中文乱码 → 一律"脚本写 UTF-8 文件 + 用 Read 工具读"，或 `iconv -f gbk -t utf-8`。
8. **核验脚本自己会撒一个"诚实的谎"**（审查意见 1 暴露）：`verify_library.mjs` 把"复位筛选"写在了截图**之前**，于是 `desktop-1440-tagwebgl.png` 截到的是未筛选首屏 —— **和首屏截图逐字节相同**（MD5 都是 `300edc483fd4…`），而脚本照样报 PASS。**看图看不出来**（版式内容都正常，只是与文件名不符），只有哈希比对才现形。→ 已把「截图存证 MD5 两两不同」加成常设判据。**教训：核验不是"跑一下脚本看它说 PASS"，而是"连脚本自己的断言也要被怀疑"。**
9. **测试脚本里的期望值不能写死**：`supplement_checks.mjs` 初版把"参考复刻 + 重 WebGL"的期望段数写成 `6`，实测是 **0** —— 结果把**产品正确**误报成 FAIL，容易引导人去改没错的东西。→ 改成从数据源现算（`expectFor(cat, tag)`）。与 `任务卡.md` 那条"76 条不能只数总数"同源：**期望值和被测对象必须来自同一个真值源，且真值要自己算。**
