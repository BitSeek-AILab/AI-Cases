一、痛点原句（引用手册原文）

手册出处： 案例 7

提示词：
分析这份简历，提取关键信息生成表格
执行效果： 自动识别简历中的姓名、教育背景、工作经历等关键信息，生成结构化表格。

提取说明： 手册此处只有「一句提示词 + 一句执行效果」，没有第二人称的痛点导入，也没有写"以前要折腾多久"的代价句。按《子Agent执行规范》第〇补节，痛点提取的三个位置（章首导入 / 案例引入 / 章末收束）在本案例均缺位。因此本卡的痛点主体为 【补全】，仅"提示词要解决什么任务 + 执行效果"部分引自原文。

二、痛点主体（【补全】）

谁： 招聘季里的 HR / 招聘专员（本案例取"一天要初筛几十份简历、还要给用人部门报汇总表的招聘专员"）。

真实的招聘季场景： 一份简历看几秒就够判断合不合适，但要把关键信息敲进汇总表，就是纯手工：

步骤手工做法代价
1. 读简历一份份打开，找姓名、学历、院校、经历每份版式都不一样，眼睛要来回找
2. 抄进表格把姓名/学历/经历敲进 Excel50 份就是 50 遍复制粘贴
3. 算工作年限从几段经历里自己加加减减最费脑：起止日期格式五花八门，多段经历要一段段算
4. 判断口径实习算不算？空窗期扣不扣？每个人算法不一样，同一个岗位的候选人没有可比性
5. 汇总上报整理成给用人部门的表敲错一个学历/年限，用人部门就筛错了人

旧做法的代价： 一天 50 份走完 2–3 小时，而且 招聘季天天发生。慢还不是最要命的——"工作年限"这一步最容易错：简历里的日期格式五花八门（2017.07-2020.06、2016年9月—2019年6月、2021.09-至今），还要判断实习算不算、中间空窗扣不扣。算错一个候选人的年限，可能就把人筛掉了。

想要的目标： 把一批简历丢进去，直接拿到 一张结构化汇总表（姓名/学历/工作年限/关键经历…），每行口径一致、可直接排序比较。不是"学会用 Excel 做筛选"，是"这批简历几秒钟变成一张能拿去汇报的表"。

【补全】为什么值得解决： 这件事的真实价值在"口径统一 + 不抄错"。人做这件事最大的风险不是慢，是每人一套算法——同批候选人一个把实习算进去了、一个没算，表面上是同一张表，实际没有可比性，筛选结论就是错的。把"读简历 → 抽字段 → 按统一口径算年限 → 汇总成表"这条链路交给 Agent，人只需要判断"这个人合不合适"，不再被"抄写和算术"淹没。口径一旦固定，下一批简历重跑即可。

三、价值归类

目标导向 ✅

要解决的是"招聘季把一批简历变成一张口径统一、可直接比较的筛选汇总表"这个业务目标。 反面想想就清楚——如果只做成"教你用 Excel 复制粘贴做候选人台账"，那是工具理性，本卡不通过。

四、本案例的"人工易错点"（复刻时特意做进素材，用来验证痛点是真的）

复刻时把下面几条做进了输入素材（5 份简历），让"手工很容易算错"变成可验证的事实：

  1. 版式不统一：有的用「教育背景」、有的用「教育经历」；有的用「工作经历」、有的用「工作经验」；实习有的单列「实习经历」小节（赵宇航），有的混在工作经历里带「（实习）」标记（王芳）。
  2. 日期格式不统一：2017.07-2020.06 / 2016年9月—2019年6月 / 2021.09 - 至今。
  3. "工作年限"三个陷阱（本案例核心）：
  • 实习不计入正式年限：王芳混在工作节里的实习、赵宇航单列的实习，混进去会多算（王芳 7.3 → 7.8 年；赵宇航 1.3 → 1.8 年）；
  • 空窗期要扣掉：陈静中间有 2 个月待业（2022.03–2022.04），按"最早开始~最近结束"整段算会多算（7.2 → 7.3 年）；
  • 多段经历要逐段相加，不能只看首尾。

这些坑"看起来都对"，但算出来的年限差 0.5–1 年，会直接改变"谁更资深"的排序。复刻产物里对三点都做了专项核对。
